# Level 8: テスト戦略・品質保証

> **目標**: テスト設計・実装ができ、品質の高いソフトウェアを作れるエンジニアになる
> **関連資格**: JSTQB認定テスト技術者、ISTQB Foundation Level

## なぜテストを学ぶのか？

```
「動くコード」と「品質の高いコード」は違う

❌ 動けばOK → バグが本番で発覚、障害対応に追われる
⭕ テストで品質を担保 → 安心してリリース、変更も恐れない
```

**シニアエンジニアの視点**:
- テストがないコードは「レガシーコード」
- AIが書いたコードこそテストで検証が必須
- リファクタリングの安全網としてのテスト

## Level 8 完了時の到達目標

### コードレビューで指摘できること

1. **テスト設計の問題**
   - テストケースの漏れ（境界値、異常系）
   - テストピラミッドのバランス崩れ
   - Flakyテストの放置

2. **テストコードの品質**
   - テスト構造の乱れ（AAA違反）
   - 過剰なモック、現実との乖離
   - アサーション漏れ

3. **CI/CDの問題**
   - テストなきデプロイ
   - 遅いパイプライン
   - カバレッジ低下の見逃し

4. **品質プロセスの問題**
   - 非機能テスト漏れ
   - AI生成コードの未検証
   - 品質メトリクスの不在

## よくあるAIの間違い（レビューで見抜くポイント）

```javascript
// ❌ AIがやりがちなミス1: アサーションが甘い
test('ユーザーを取得できる', async () => {
  const user = await getUser(1);
  expect(user).toBeTruthy(); // 存在確認だけ
});

// ⭕ 正しいテスト
test('ユーザーを取得できる', async () => {
  const user = await getUser(1);
  expect(user.id).toBe(1);
  expect(user.name).toBe('太郎');
  expect(user.email).toMatch(/@/);
});
```

```javascript
// ❌ AIがやりがちなミス2: 実装の詳細をテスト
test('内部メソッドが呼ばれる', () => {
  const spy = jest.spyOn(service, '_internalMethod');
  service.process();
  expect(spy).toHaveBeenCalled(); // 実装詳細への依存
});

// ⭕ 振る舞いをテスト
test('処理結果が正しい', () => {
  const result = service.process();
  expect(result.status).toBe('completed');
});
```

```javascript
// ❌ AIがやりがちなミス3: ハッピーパスのみ
test('ログインできる', async () => {
  await login('user@example.com', 'password123');
  expect(isLoggedIn()).toBe(true);
});

// ⭕ 異常系もテスト
describe('ログイン', () => {
  test('正しい認証情報でログインできる', async () => { ... });
  test('間違ったパスワードでエラーになる', async () => { ... });
  test('存在しないユーザーでエラーになる', async () => { ... });
  test('空のパスワードでエラーになる', async () => { ... });
  test('ロックアウト後にログインできない', async () => { ... });
});
```
