# Level 0: AI時代のエンジニアとして

> **「コードを書く人」から「問題を解決する人」へ**

## 🔥 最も大事なこと

### 2026年、エンジニアの役割は変わった

(出典: [@IT](https://atmarkit.itmedia.co.jp/ait/articles/2601/06/news007.html))

```
2020年: エンジニア = コードを書く人
2026年: エンジニア = AIを使って問題を解決する人
```

**役割のシフト:**
| Before | After |
|--------|-------|
| How（どう実装するか） | Why（なぜ作るのか）/ What（何を作るのか） |
| コードを書く | AIが書いたコードをレビューする |
| 作業する | 評価・検証・環境整備する |

> "従来型のコーディング作業そのものは、もはやエンジニアの役割の中心ではなくなりつつある"

---

## 📐 このカリキュラムの狙い

### なぜ「読む力」を最優先するのか

(出典: [DEV Community](https://dev.to/naveens16/the-2026-computer-science-playbook-how-to-learn-where-to-focus-and-what-it-really-takes-to-get-3nm1))

```
AIはコードを「書ける」
でも、AIは自分のコードの「正しさを保証できない」

だから人間が「読んで・判断する」必要がある
```

**AIが苦手なこと:**
- ビジネス要件との整合性判断
- セキュリティリスクの文脈理解
- パフォーマンスのトレードオフ判断
- 「本当にこれでいいのか？」という問い

**だからこそ身につけるべき力:**
1. **読む力** - コードを見て問題を発見できる
2. **判断する力** - 正しいか間違いか決められる
3. **説明する力** - なぜダメか言語化できる

## 🧠 AI時代に必要なマインドセット

### 1. 「書ける」より「見抜ける」

(出典: [Agenticai Flow](https://agenticai-flow.com/posts/ai-era-software-engineer-survival-guide/))

```
❌ 「自分でコード書けます！」
⭕ 「AIが書いたコードの問題点を指摘できます」
```

AIは秒速でコードを生成する。でも：
- **論理エラー**を混入させる
- **セキュリティ脆弱性**を見落とす
- **パフォーマンス問題**を作り込む

これを見抜けるのが「シニアエンジニア」

### 2. 基礎は変わらない、むしろ重要になる

(出典: [DEV Community](https://dev.to/naveens16/the-2026-computer-science-playbook-how-to-learn-where-to-focus-and-what-it-really-takes-to-get-3nm1))

> "AI isn't killing Computer Science — it's restoring the importance of what Computer Science truly is"

```
AIが汎用コードを書けるからこそ、
深い専門性の価値はむしろ高まる
```

**変わらない基礎:**
- アルゴリズムとデータ構造
- システム設計の原則
- セキュリティの基本
- ネットワークの仕組み

### 3. 「AIを使う人」が勝つ

(出典: [codebasics](https://codebasics.io/blog/software-engineer-2-0-how-to-survive-and-thrive-in-the-ai-era))

> "AI probably isn't taking your job. But another engineer who knows how to use it properly might."

```
AIを恐れる必要はない
AIを使えない人が淘汰される
```

**AI活用スキル:**
- プロンプトエンジニアリング
- AIの出力を評価する目
- AIと協働するワークフロー設計

## 📊 2026年に求められる4つの役割

(出典: [@IT](https://atmarkit.itmedia.co.jp/ait/articles/2601/06/news007.html))

| 役割 | 説明 | 必要なスキル |
|------|------|-------------|
| **コーディング** | AI開発ツールを使いこなし実装を進める | AIツール活用、基礎文法理解 |
| **設計** | 要件を構造化し、AIに適切に指示できる | 要件定義、システム設計 |
| **コードレビュー** | 生成コードの品質を判断して修正できる | 読解力、問題発見力 |
| **オーケストレーション** | 全体を統括・調整する | PM力、コミュニケーション |

## ⚠️ AI時代の落とし穴

### やってはいけないこと

**1. AIにコードを書かせて「動いたからOK」**
```
❌ AI生成 → 動作確認 → デプロイ
⭕ AI生成 → レビュー → 理解 → 修正 → テスト → デプロイ
```

**2. 基礎をスキップしてフレームワークから入る**
(出典: [Scaler](https://www.scaler.com/blog/javascript-roadmap/))
> "Developers who learned React without understanding JavaScript got stuck when they hit problems requiring understanding of closures or async behavior."

**3. AIの出力を鵜呑みにする**
- AIは自信満々に間違える
- ハルシネーション（嘘）を見抜く力が必要
- 常に「本当か？」と疑う姿勢


## 🚀 学習の心構え

### 1. 「なぜ」を常に問う
```
❌ 「こう書けばいい」で止まる
⭕ 「なぜこう書くべきか」まで理解する
```

### 2. 失敗を恐れない
```
バグを経験 → 次から見抜ける
エラーを経験 → 原因を理解できる
```

### 3. アウトプットを続ける
```
読む → 書く → 教える
理解度は「教えられるか」で測る
```

### 4. AIは道具、判断は人間
```
AIに書かせる → 自分がレビュー → 責任は自分
```
