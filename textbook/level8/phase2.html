FIRST原則は、良い単体テストの5つの特性です。

📊 FIRST原則

各原則の詳細

原則 意味 違反例
Fast 高速に実行できる DBアクセスで遅い
Isolated 他のテストに依存しない テスト順序に依存
Repeatable 何度実行しても同じ結果 乱数や日時に依存
Self-validating 自動で成功/失敗を判定 目視確認が必要
Timely 適切なタイミングで書く リリース後にテスト

AAAパターン

📋 Arrange - Act - Assert 
test('ユーザーを作成できる', () => {
  // Arrange（準備）
  const userData = { name: '太郎', email: 'taro@example.com' };

  // Act（実行）
  const user = createUser(userData);

  // Assert（検証）
  expect(user.id).toBeDefined();
  expect(user.name).toBe('太郎');
});

Given-When-Then

📋 BDDスタイル 
describe('ユーザー作成', () => {
  test('有効なデータが与えられたとき、ユーザーが作成される', () => {
    // Given（前提条件）
    const userData = { name: '太郎', email: 'taro@example.com' };

    // When（操作）
    const user = createUser(userData);

    // Then（期待結果）
    expect(user.id).toBeDefined();
    expect(user.name).toBe('太郎');
  });
});
構造化されていない
test('test', () => {
  const x = func(1);
  expect(x).toBe(2);
  const y = func(x);
  expect(y).toBe(4);
  // 何がArrange? Act? Assert?
});
構造化されている
test('2倍にする', () => {
  // Arrange
  const input = 1;
  // Act
  const result = double(input);
  // Assert
  expect(result).toBe(2);
});

アサーションとは

アサーションとは、テストの期待値を検証する文です。

🔧 Jestのアサーション例 
// 等価
expect(value).toBe(1);           // 厳密等価（===）
expect(value).toEqual({a: 1});   // 深い等価

// 真偽値
expect(value).toBeTruthy();      // 真っぽい値
expect(value).toBeFalsy();       // 偽っぽい値
expect(value).toBeNull();        // null

// 数値
expect(value).toBeGreaterThan(3);
expect(value).toBeLessThanOrEqual(5);

// 配列・文字列
expect(array).toContain('item');
expect(string).toMatch(/pattern/);

// エラー
expect(() => func()).toThrow();
expect(() => func()).toThrow('message');

アサーションの注意点

❌ AIがやりがちな間違い 
// ❌ 甘いアサーション
test('ユーザーを取得', async () => {
  const user = await getUser(1);
  expect(user).toBeTruthy(); // 存在だけ確認
});

// ⭕ 適切なアサーション
test('ユーザーを取得', async () => {
  const user = await getUser(1);
  expect(user.id).toBe(1);
  expect(user.name).toBe('太郎');
  expect(user.email).toMatch(/@/);
});

テストダブルとは

テストダブルとは、テストで本物の依存オブジェクトの代わりに使う偽物です。
映画のスタントダブル（代役）が語源。

📊 5種類のテストダブル
種類 目的 例
Dummy 引数を埋めるだけ 使わない引数にnull
Stub 固定値を返す APIが常に成功を返す
Spy 呼び出しを記録 何回呼ばれたか確認
Mock 期待値を事前に設定 特定の引数で呼ばれることを検証
Fake 簡易的な実装 インメモリDB

Mockとは

Mockは、期待する呼び出しを事前に設定し、検証するテストダブルです。

🔧 Jestでのモック 
// モジュール全体をモック
jest.mock('./api');

// 関数をモック
const mockFn = jest.fn();
mockFn.mockReturnValue('hello');

// 呼び出しを検証
expect(mockFn).toHaveBeenCalled();
expect(mockFn).toHaveBeenCalledWith('arg');
expect(mockFn).toHaveBeenCalledTimes(2);

過剰なモックの問題

⚠️ モックの罠
  • 実装詳細への依存：内部実装が変わるとテストが壊れる
  • 本番との乖離：モックと本物の動作が違う可能性
  • 過信：モックは成功するが本番で失敗
過剰なモック
// ❌ 内部実装をモック
test('process', () => {
  const spy = jest.spyOn(
    service, '_internalHelper'
  );
  service.process();
  expect(spy).toHaveBeenCalled();
});
振る舞いをテスト
// ⭕ 外部から見た振る舞い
test('process', () => {
  const result = service.process();
  expect(result.status).toBe('ok');
});

Stubとは

Stubは、固定の戻り値を返すテストダブルです。外部依存を排除できます。

🔧 Stubの例 
// API呼び出しをスタブ
jest.spyOn(api, 'fetchUser').mockResolvedValue({
  id: 1,
  name: '太郎'
});

// テスト
test('ユーザー情報を表示', async () => {
  const result = await displayUser(1);
  expect(result).toContain('太郎');
});

Stubの注意点

⚠️ 本番との乖離

Stubは常に期待通りの値を返しますが、本番のAPIは：

  • エラーを返すかもしれない
  • タイムアウトするかもしれない
  • 予期しないデータ形式かもしれない

→ 異常系のStubも用意する

セットアップとティアダウン

🔧 ライフサイクル 
describe('Database', () => {
  // 全テスト前に1回
  beforeAll(async () => {
    await db.connect();
  });

  // 各テスト前
  beforeEach(() => {
    db.clear();
  });

  // 各テスト後
  afterEach(() => {
    db.rollback();
  });

  // 全テスト後に1回
  afterAll(async () => {
    await db.disconnect();
  });
});

async/awaitでテスト

🔧 非同期テストの書き方 
// async/await
test('ユーザーを取得できる', async () => {
  const user = await fetchUser(1);
  expect(user.name).toBe('太郎');
});

// Promiseを返す
test('ユーザーを取得できる', () => {
  return fetchUser(1).then(user => {
    expect(user.name).toBe('太郎');
  });
});

// resolves/rejects マッチャー
test('成功を返す', async () => {
  await expect(fetchUser(1)).resolves.toHaveProperty('name');
});

test('エラーを返す', async () => {
  await expect(fetchUser(-1)).rejects.toThrow('Invalid ID');
});

タイマーのテスト

⏱️ Fake Timers 
// タイマーをモック

test('1秒後にコールバックが呼ばれる', () => {
  const callback = jest.fn();
  setTimeout(callback, 1000);

  // 1秒進める
  jest.advanceTimersByTime(1000);

  expect(callback).toHaveBeenCalled();
});

// 元に戻す
afterEach(() => {
  jest.useRealTimers();
});

カバレッジ

  • コードカバレッジとは
  • カバレッジの種類

カバレッジとは

コードカバレッジは、テストがコードのどれだけを実行したかを示す指標です。

種類 意味
行カバレッジ 実行された行の割合
分岐カバレッジ if/elseの全分岐を通過した割合
関数カバレッジ 呼び出された関数の割合
文カバレッジ 実行された文の割合

カバレッジの罠

⚠️ カバレッジ100%の落とし穴 
// カバレッジ100%でもバグがある例
function divide(a, b) {
  return a / b;  // b=0 でInfinityになる
}

test('割り算', () => {
  expect(divide(10, 2)).toBe(5);
  // カバレッジ100%だが、b=0のテストがない
});

カバレッジは「テストされていない箇所」を見つけるツールであり、
「テストの品質」を保証するものではない。

テストしにくいコード

❌ テスト困難な例 
// ❌ 直接依存
function getUser(id) {
  const db = new Database();  // 直接生成
  return db.query(`SELECT * FROM users WHERE id = ${id}`);
}

// テストでDBを差し替えられない

依存性注入（DI）

✅ テスト可能な設計 
// ⭕ 依存性注入
function getUser(id, db) {
  return db.query(`SELECT * FROM users WHERE id = ${id}`);
}

// テストでモックを注入できる
test('ユーザーを取得', () => {
  const mockDb = {
    query: jest.fn().mockReturnValue({ id: 1, name: '太郎' })
  };
  const user = getUser(1, mockDb);
  expect(user.name).toBe('太郎');
});

純粋関数

副作用あり
let total = 0;
function addToTotal(n) {
  total += n;  // 外部状態を変更
  return total;
}
純粋関数
function add(a, b) {
  return a + b;  // 入力のみで出力が決まる
}
