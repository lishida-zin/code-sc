1. HTMLとは？

このセクションで学ぶこと
  • HTMLの正体と役割
  • なぜHTMLが必要なのか
  • HTMLとCSSの違い

たとえ話：家の設計図

Webページを「家」に例えると：

  • HTML = 設計図・骨組み（どこに何があるか）
  • CSS = インテリア・外装（どう見えるか）
  • JavaScript = 電気・水道（どう動くか）

HTMLだけでは「白い壁にシンプルな家具が並んだ部屋」。見た目は地味でも、構造がしっかりしていることが最も重要です。

語源を知る

HTML = HyperText Markup Language

  • HyperText：リンクで繋がるテキスト（超越したテキスト）
  • Markup：印をつける（「ここは見出し」「ここは段落」と印をつける）
  • Language：言語（ブラウザが理解できる言語）

HTMLの本質：「意味」を伝える

重要な考え方

HTMLは「見た目」ではなく「意味」を定義します。

<h1>見出し</h1>  → ブラウザ「これは一番重要な見出しだ」
<p>段落</p>      → ブラウザ「これは本文の段落だ」

見た目を変えるのはCSSの仕事。HTMLは「これが何か」を伝えるだけ。

なぜ「意味」が重要？

対象 HTMLの「意味」をどう使うか
検索エンジン（Google） h1を見て「このページの主題」を理解
スクリーンリーダー 見出しを読み上げて視覚障害者をナビゲート
他の開発者 コードを読んで構造を即座に把握
開発思想：セマンティック（意味論的）

WHY（なぜ）：機械も人間も、文書の「意味」を理解したい

HOW（どうやって）：タグに意味を持たせる（h1=見出し、p=段落）

EFFECT（効果）：SEO向上、アクセシビリティ向上、保守性向上

確認クイズ

HTMLの主な役割は何ですか？

レビュー観点
  • 見た目のためにタグを選んでいないか？（例：太字にしたいからh1を使う→NG）
  • 適切なタグで「意味」を伝えているか？

2. タグの基本構造

このセクションで学ぶこと
  • タグの構造（開始・終了・内容）
  • 属性の書き方と役割
  • 空要素（閉じタグ不要なタグ）
  • よくある間違いと見分け方

タグの基本形

<タグ名>内容</タグ名>

例：
<p>これは段落です</p>
↑開始タグ   ↑内容    ↑終了タグ

タグは「箱」のようなもの。開始タグで箱を開け、終了タグで箱を閉じる。中に入れた「内容」がブラウザに表示されます。

属性：タグに追加情報を与える

<タグ名 属性名="属性値">内容</タグ名>

例：
<a href="https://example.com">リンク</a>
   ↑属性名  ↑属性値

属性はタグに「追加の説明」を与えます。例えば<a>タグのhref属性は「どこにリンクするか」を指定します。

属性のルール

ルール 良い例 悪い例
属性名は小文字 href="..." HREF="..."
値はダブルクォートで囲む class="box" class=box
開始タグにのみ記述 <a href="..."> </a href="...">

空要素（閉じタグ不要）

一部のタグは「中身」を持たないため、終了タグが不要です。

<br>      改行
<hr>      水平線
<img>     画像
<input>   入力欄
<meta>    メタ情報
<link>    外部リソース
なぜ空要素が存在する？

空要素は「内容を囲む」のではなく「何かを挿入・配置する」役割です。

  • <br>：ここに改行を挿入
  • <img>：ここに画像を配置
  • <input>：ここに入力欄を配置

囲む内容がないので、終了タグは不要というわけです。

よくある間違い

❌ 終了タグ忘れ 
<p>段落1
<p>段落2

ブラウザが自動補完するため動くことがあるが、予期せぬバグの原因になる。

❌ タグの入れ子が崩れている 
<p><strong>太字</p></strong>

正しくは：<p><strong>太字</strong></p>

「先に開けたら、後に閉じる」（LIFO: Last In, First Out）

❌ 属性値のクォート忘れ 
<a href=https://example.com>リンク</a>

スペースを含むURLで壊れる。必ずダブルクォートで囲む。

確認クイズ

次のコードの問題点は？

<p><a href="test.html">リンク</p></a>
レビュー観点
  • すべてのタグが正しく閉じられているか？
  • 入れ子の順序は正しいか？（開いた順の逆順で閉じる）
  • 属性値はダブルクォートで囲まれているか？

3. 文書構造（html / head / body）

このセクションで学ぶこと
  • HTML文書の必須構造
  • DOCTYPE宣言の意味
  • head要素とbody要素の違い
  • meta要素の役割

HTML文書の全体像

<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>ページタイトル</title>
</head>
<body>
  ここに表示する内容
</body>
</html>

各部分の役割

DOCTYPE宣言

<!DOCTYPE html>

「このファイルはHTML5で書かれています」とブラウザに宣言。必ず1行目に書く。

html要素

<html lang="ja">...</html>

HTML文書全体を囲む「ルート要素」。lang属性で言語を指定（"ja"=日本語）。

なぜlangが必要？

  • スクリーンリーダーが正しい発音で読み上げる
  • 検索エンジンが言語を判別
  • ブラウザの翻訳機能が動作

head要素：見えない情報

<head>...</head>

ページ自体の「メタ情報」を記述。ユーザーには直接見えない。

要素 役割
<meta charset="UTF-8"> 文字コード指定（日本語が文字化けしない）
<meta name="viewport"...> スマホ対応（レスポンシブの基盤）
<title> ブラウザのタブに表示されるタイトル
<link> 外部CSSの読み込み
<script> 外部JSの読み込み

body要素：見える内容

<body>...</body>

ユーザーに見える内容をすべてここに書く。

body = 「体」。Webページの「本体」という意味。

開発思想：関心の分離

WHY：メタ情報と表示内容を混ぜると管理が大変

HOW：head（設定）とbody（内容）を分離

EFFECT：役割が明確、保守しやすい、SEOツールが解析しやすい

よくある間違い

❌ titleをbodyに書く 
<body>
  <title>ページタイトル</title> ← NG！
</body>

titleはhead内に書く。bodyに書くとタブに表示されない。

❌ charset指定を忘れる

日本語が「譁�蟄怜喧縺代」のように文字化けする原因。必ず<meta charset="UTF-8">を入れる。

❌ viewport指定を忘れる

スマホで見たとき、PCサイズのまま縮小表示されてしまう。

確認クイズ

<meta charset="UTF-8">は何のため？

レビュー観点
  • DOCTYPE宣言が1行目にあるか？
  • html要素にlang属性があるか？
  • charset、viewport、titleがhead内にあるか？
  • 表示コンテンツはすべてbody内か？

4. テキスト要素

このセクションで学ぶこと
  • 見出し（h1〜h6）の使い方
  • 段落（p）と改行（br）の違い
  • 強調（strong, em）の意味

見出し要素：h1〜h6

<h1>最重要の見出し</h1>
<h2>次に重要な見出し</h2>
<h3>その次</h3>
...
<h6>最も細かい見出し</h6>

h = heading（見出し）。数字が小さいほど重要度が高い。

見出しのルール

ルール 理由
h1は1ページに1つ ページの主題を表す。2つ以上あると混乱
レベルを飛ばさない h1→h3のように飛ばすと構造が不明瞭
見た目ではなく意味で選ぶ 大きい文字にしたいからh1→NG
❌ よくある間違い 
<h1>会社名</h1>
<h3>サービス紹介</h3>  ← h2を飛ばしている！

段落と改行

<p>これは1つの段落です。</p>
<p>これは別の段落です。</p>

<p>1行目<br>2行目</p>  ← 同じ段落内で改行
要素 用途
<p> 段落（話のまとまり）を作る
<br> 同じ段落内での改行（住所、詩など）
❌ br連打でスペースを作る 
<p>内容</p>
<br><br><br>  ← NG！CSSでmarginを使う

強調要素

<strong>重要なテキスト</strong>  → 強い強調（太字）
<em>強調テキスト</em>          → 軽い強調（斜体）

strong = 強い、em = emphasis（強調）

bタグとstrongタグの違い
  • <b>：見た目だけ太字（意味なし）
  • <strong>：意味的に重要（スクリーンリーダーが強調）

→ 現代のHTMLでは<strong>を使う

5. リンクと画像

このセクションで学ぶこと
  • aタグ（リンク）の使い方
  • imgタグ（画像）の使い方
  • 必須属性と推奨属性
  • セキュリティとアクセシビリティ

リンク：aタグ

<a href="https://example.com">リンクテキスト</a>

a = anchor（アンカー、錨）：ページとページを繋ぐ「錨」

href = hypertext reference：参照先のURL

リンクの種類

種類 例
外部リンク href="https://example.com"
内部リンク href="/about.html"
ページ内リンク href="#section1"
メールリンク href="mailto:test@example.com"

target属性

<a href="..." target="_blank">新しいタブで開く</a>
セキュリティ注意！

target="_blank"を使う場合、必ずrel="noopener noreferrer"を付ける。

<a href="..." target="_blank" rel="noopener noreferrer">安全</a>

理由：リンク先のページがwindow.openerで元ページを操作できてしまう脆弱性を防ぐ。

画像：imgタグ

<img src="image.jpg" alt="画像の説明">

src = source（ソース）：画像ファイルのパス

alt = alternative（代替）：画像が表示できないときの代替テキスト

alt属性は必須！
  • 画像が読み込めないときに表示される
  • スクリーンリーダーが読み上げる
  • SEOに影響する

装飾目的の画像はalt=""（空）にする。

推奨属性

<img src="photo.jpg" alt="説明" width="800" height="600" loading="lazy">
属性 効果
width / height レイアウトシフト防止（表示が安定）
loading="lazy" 遅延読み込み（スクロールするまで読まない）

6. リスト

このセクションで学ぶこと
  • 順序なしリスト（ul）
  • 順序ありリスト（ol）
  • 定義リスト（dl）

順序なしリスト：ul + li

<ul>
  <li>項目1</li>
  <li>項目2</li>
  <li>項目3</li>
</ul>

ul = unordered list（順序なしリスト）

li = list item（リスト項目）

用途：メニュー、タグ一覧、順番が関係ない列挙

順序ありリスト：ol + li

<ol>
  <li>手順1</li>
  <li>手順2</li>
  <li>手順3</li>
</ol>

ol = ordered list（順序ありリスト）

用途：手順、ランキング、順番が重要な列挙

定義リスト：dl + dt + dd

<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>

  <dt>CSS</dt>
  <dd>Cascading Style Sheets</dd>
</dl>

dl = description list（説明リスト）

dt = description term（用語）

dd = description details（説明）

用途：用語集、FAQ、キー・バリュー形式

❌ よくある間違い 
<ul>
  項目1  ← liで囲んでいない！
  <li>項目2</li>
</ul>

ul/olの直下にはliのみ。テキストを直接書かない。

7. セマンティックHTML

Phase 1 最重要セクション

このセクションの理解が「プロ」と「初心者」を分ける。

このセクションで学ぶこと
  • セマンティックHTMLとは何か
  • 主要なセマンティック要素
  • divとの違い
  • 実務でのレビュー観点

セマンティックとは？

Semantic = 意味論的

タグ自体が「これは何か」を示すHTML。

❌ 意味のないHTML
<div class="header">...</div>
<div class="nav">...</div>
<div class="main">...</div>

✅ セマンティックHTML
<header>...</header>
<nav>...</nav>
<main>...</main>

なぜセマンティックが重要？

対象 divだと... セマンティックだと...
検索エンジン 構造を理解できない main=本文と理解、SEO向上
スクリーンリーダー 「division」としか読まない 「navigation」と案内
開発者 class名を見ないと不明 タグ名で構造が一目瞭然

主要なセマンティック要素

ページ構造

要素 意味 用途
<header> ヘッダー ページやセクションの導入部
<nav> ナビゲーション メニュー、リンク集
<main> メインコンテンツ ページの主要な内容（1ページに1つ）
<article> 独立した記事 ブログ記事、ニュース記事
<section> セクション テーマでグループ化された内容
<aside> 補足情報 サイドバー、関連リンク
<footer> フッター 著作権、連絡先

典型的なページ構造

<body>
  <header>
    <nav>メニュー</nav>
  </header>

  <main>
    <article>
      <h1>記事タイトル</h1>
      <section>セクション1</section>
      <section>セクション2</section>
    </article>
  </main>

  <aside>サイドバー</aside>

  <footer>コピーライト</footer>
</body>

divを使うべき場面

divは「意味がない」ときに使う

  • CSSでスタイルを当てるためだけのラッパー
  • JavaScriptで操作するためだけのコンテナ

意味がある場合はセマンティック要素を使う。

開発思想：セマンティックWeb

WHY：機械（検索エンジン、支援技術）が文書の意味を理解したい

HOW：タグに意味を持たせ、構造を明示

EFFECT：SEO向上、アクセシビリティ向上、保守性向上、AI解析精度向上

レビュー観点（実務で重要）

シニアが見るポイント
  1. div地獄：divだらけになっていないか？
  2. header/footer：適切に使われているか？
  3. nav：ナビゲーションに使われているか？
  4. main：1ページに1つだけか？
  5. article vs section：独立記事かセクションか区別できているか？

8. CSSとは？

このセクションで学ぶこと
  • CSSの役割と目的
  • CSSの3つの適用方法
  • カスケードの基本概念

たとえ話：家のインテリア

HTMLが「家の骨組み（柱、壁、部屋の配置）」なら、CSSは「インテリア」です。

  • 壁の色を決める
  • 家具の配置を決める
  • 照明の雰囲気を決める

骨組み（HTML）が同じでも、インテリア（CSS）を変えれば全く違う印象の家になります。

語源を知る

CSS = Cascading Style Sheets

  • Cascading：滝のように流れ落ちる → スタイルが優先度順に適用される
  • Style：見た目、デザイン
  • Sheets：シート、設定書

CSSの3つの適用方法

方法 書き方 推奨度
外部CSS <link rel="stylesheet" href="style.css"> 推奨
内部CSS <style>...</style> 状況次第
インラインCSS style="..." 避ける
なぜ外部CSSが推奨？
  • 関心の分離：HTML（構造）とCSS（見た目）を別ファイルに
  • 再利用性：複数ページで同じCSSを共有
  • キャッシュ：ブラウザがCSSをキャッシュして高速化

CSSの基本構文

セレクタ {
  プロパティ: 値;
  プロパティ: 値;
}

例：
p {
  color: blue;
  font-size: 16px;
}
用語 意味 例
セレクタ どの要素にスタイルを適用するか p, .class, #id
プロパティ 何を変えるか color, font-size
値 どう変えるか blue, 16px
開発思想：関心の分離

WHY：構造（HTML）と見た目（CSS）を混ぜると管理が大変

HOW：HTMLは構造のみ、CSSは見た目のみを担当

EFFECT：保守しやすい、デザイン変更が容易、チーム開発に最適

CSSを適用する方法として最も推奨されるのは？

9. セレクタ

CSS最重要セクション

セレクタを理解しないとCSSは読めない。ここをしっかり押さえる。

このセクションで学ぶこと
  • 基本セレクタ（要素、クラス、ID）
  • 結合セレクタ（子孫、子、隣接）
  • 詳細度（優先順位）の仕組み

基本セレクタ

セレクタ 書き方 意味 詳細度
要素セレクタ p すべてのp要素 0-0-1
クラスセレクタ .box class="box"の要素 0-1-0
IDセレクタ #header id="header"の要素 1-0-0
全称セレクタ * すべての要素 0-0-0 
/* 要素セレクタ */
p { color: black; }

/* クラスセレクタ（.で始まる） */
.highlight { background: yellow; }

/* IDセレクタ（#で始まる） */
#main-title { font-size: 32px; }

クラスとIDの違い

クラス (.class) ID (#id)
使用回数 何度でも使える 1ページに1回のみ
用途 スタイル適用（推奨） ページ内リンク、JS操作
詳細度 低い 高い

実務では：クラスを使う、IDはCSSでは避ける

結合セレクタ

セレクタ 書き方 意味
子孫セレクタ div p div内のすべてのp（深さ問わず）
子セレクタ div > p divの直接の子のpのみ
隣接セレクタ h1 + p h1の直後のp
一般兄弟 h1 ~ p h1の後のすべてのp（兄弟要素） 
/* 子孫セレクタ：nav内のすべてのa */
nav a { color: white; }

/* 子セレクタ：ulの直接の子のliのみ */
ul > li { list-style: none; }

/* 隣接セレクタ：h2の直後のp */
h2 + p { font-weight: bold; }

詳細度（Specificity）

CSSが「効かない」原因の90%は詳細度

詳細度 = どのセレクタが優先されるかを決める点数

計算方法：(ID, クラス, 要素)

#header      → (1, 0, 0) = 100点
.nav .link   → (0, 2, 0) = 20点
div p        → (0, 0, 2) = 2点

点数が高いほうが勝つ
❌ !important の乱用 
p { color: red !important; } /* 最終手段。使わない設計にすべき */

!importantは「詳細度を無視して最優先」。使うと保守が困難に。

開発思想：KISS原則

KISS = Keep It Simple, Stupid（シンプルに保て）

WHY：複雑なセレクタは読みにくく、保守困難

HOW：クラスを使い、ネストは浅く

EFFECT：誰でも理解でき、変更しやすい

12. ボックスモデル

CSS超重要概念

すべてのHTML要素は「ボックス」として扱われる。これを理解しないとレイアウトは組めない。

このセクションで学ぶこと
  • ボックスモデルの4層構造
  • margin, padding, border の違い
  • box-sizing の重要性

ボックスモデルの構造

┌─────────────────────────────────┐
│           margin（外側の余白）    │
│  ┌───────────────────────────┐  │
│  │      border（境界線）       │  │
│  │  ┌─────────────────────┐  │  │
│  │  │  padding（内側の余白）│  │  │
│  │  │  ┌───────────────┐  │  │  │
│  │  │  │   content     │  │  │  │
│  │  │  │  （内容領域）   │  │  │  │
│  │  │  └───────────────┘  │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
プロパティ 意味 特徴
content 内容（テキスト、画像等） width, heightで指定
padding 内側の余白 背景色が適用される
border 境界線 色・太さ・スタイル
margin 外側の余白 透明、要素間の間隔

margin と padding の書き方

/* 4方向すべて同じ */
margin: 10px;

/* 上下 / 左右 */
margin: 10px 20px;

/* 上 / 左右 / 下 */
margin: 10px 20px 30px;

/* 上 / 右 / 下 / 左（時計回り） */
margin: 10px 20px 30px 40px;

/* 個別指定 */
margin-top: 10px;
margin-right: 20px;
margin-bottom: 30px;
margin-left: 40px;

box-sizing（超重要）

問題：width を指定しても意図通りにならない 
/* デフォルト（content-box） */
.box {
  width: 100px;
  padding: 20px;
  border: 5px solid black;
}
/* → 実際の幅 = 100 + 20*2 + 5*2 = 150px */
解決策：box-sizing: border-box 
/* border-box を指定 */
.box {
  box-sizing: border-box;
  width: 100px;
  padding: 20px;
  border: 5px solid black;
}
/* → 実際の幅 = 100px（padding, borderを含む） */

/* 全要素に適用（推奨） */
*, *::before, *::after {
  box-sizing: border-box;
}

margin の相殺（Collapse）

縦方向のmarginは「相殺」される（大きい方だけが適用）

<div style="margin-bottom: 30px">上</div>
<div style="margin-top: 20px">下</div>

/* 間隔は 30px + 20px = 50px ではなく、30px */

これを知らないと「余白が効かない」と悩むことに。

13. Flexbox

現代レイアウトの基本

横並び、中央揃え、均等配置。これらは全部Flexboxで解決。

このセクションで学ぶこと
  • Flexboxの基本概念
  • 親要素（コンテナ）のプロパティ
  • 子要素（アイテム）のプロパティ
  • よくあるパターン

Flexboxの有効化

.container {
  display: flex;
}

/* これだけで子要素が横並びになる */

主軸と交差軸

flex-direction: row（デフォルト）の場合

主軸（main axis）→→→→→→→→→→
↓ ┌───┐ ┌───┐ ┌───┐
交 │ 1 │ │ 2 │ │ 3 │
差 └───┘ └───┘ └───┘
軸
（cross axis）

justify-content → 主軸方向の配置
align-items     → 交差軸方向の配置

コンテナ（親）のプロパティ

プロパティ 値 効果
flex-direction row / column 横並び / 縦並び
justify-content flex-start / center / flex-end / space-between / space-around 主軸方向の配置
align-items flex-start / center / flex-end / stretch 交差軸方向の配置
flex-wrap nowrap / wrap 折り返すかどうか
gap 10px など アイテム間の間隔

よく使うパターン

中央揃え（上下左右中央） 
.container {
  display: flex;
  justify-content: center;  /* 横方向中央 */
  align-items: center;      /* 縦方向中央 */
  height: 100vh;
}
両端揃え（ヘッダーのロゴとナビ） 
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
等間隔で並べる 
.nav {
  display: flex;
  gap: 20px;  /* アイテム間を20pxずつ空ける */
}

アイテム（子）のプロパティ

/* 余ったスペースの配分 */
.item {
  flex-grow: 1;   /* 余白を均等に分配 */
}

/* 縮む比率 */
.item {
  flex-shrink: 0; /* 縮まない */
}

/* 基準サイズ */
.item {
  flex-basis: 200px;
}

/* 一括指定 */
.item {
  flex: 1;        /* grow: 1, shrink: 1, basis: 0% */
}

過去：横並びは float: left で実現（clearfixなど面倒）

現在：Flexboxで簡単・直感的に実現

→ floatはレイアウトには使わない。画像の回り込みのみ。

14. Grid

2次元レイアウトの決定版

Flexboxは1次元（行 or 列）、Gridは2次元（行 と 列）を同時に扱える。

このセクションで学ぶこと
  • Gridの基本概念
  • グリッドの定義方法
  • アイテムの配置
  • FlexboxとGridの使い分け

Gridの有効化

.container {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;  /* 3列 */
  grid-template-rows: 100px 200px;      /* 2行 */
  gap: 20px;                            /* 間隔 */
}

単位: fr（fraction）

/* frは「余ったスペースの比率」 */
grid-template-columns: 1fr 2fr 1fr;
/* → 1:2:1 の比率で分割 */

grid-template-columns: 200px 1fr;
/* → 左は固定200px、残りを右が取る */

grid-template-columns: repeat(3, 1fr);
/* → 1fr 1fr 1fr と同じ */

よく使うパターン

カードレイアウト（レスポンシブ） 
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 20px;
}
/* → 最小250px、それ以上なら均等に広がる */
/* → 幅に応じて自動的に列数が変わる */
Holy Grailレイアウト 
.layout {
  display: grid;
  grid-template-areas:
    "header header header"
    "nav    main   aside"
    "footer footer footer";
  grid-template-columns: 200px 1fr 200px;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}

.header { grid-area: header; }
.nav    { grid-area: nav; }
.main   { grid-area: main; }
.aside  { grid-area: aside; }
.footer { grid-area: footer; }

アイテムの配置

/* 行と列の位置を指定 */
.item {
  grid-column: 1 / 3;  /* 1列目から3列目の手前まで（2列分） */
  grid-row: 1 / 2;     /* 1行目 */
}

/* spanで範囲指定 */
.item {
  grid-column: span 2;  /* 2列分 */
}

FlexboxとGridの使い分け

状況 適切な選択
横一列に並べる Flexbox
中央揃え Flexbox
カードを格子状に並べる Grid
ページ全体のレイアウト Grid
内容に応じて伸縮 Flexbox
明確な行×列構造 Grid
シンプルなルール

1次元（横 or 縦）→ Flexbox

2次元（横 と 縦）→ Grid

:has() セレクタ（親セレクタ）

従来の問題：CSSは「親→子」の方向にしかスタイルを適用できなかった

:has()の登場：「特定の子を持つ親」を選択できるように！

/* 画像を含むカードだけスタイルを変える */
.card:has(img) {
  padding: 0;
}

/* チェックされたラベルのスタイルを変える */
label:has(input:checked) {
  background: lightblue;
}

/* 空のセクションを非表示 */
section:has(:empty) {
  display: none;
}

Container Queries（コンテナクエリ）

従来の問題：メディアクエリは「画面幅」基準。コンポーネントの「親要素の幅」基準ではない

Container Queriesの登場：コンテナ（親要素）のサイズに応じてスタイルを変更！

/* コンテナを定義 */
.card-container {
  container-type: inline-size;
  container-name: card;
}

/* コンテナの幅に応じてスタイル変更 */
@container card (min-width: 400px) {
  .card {
    display: flex;
    flex-direction: row;
  }
}

@container card (max-width: 399px) {
  .card {
    display: block;
  }
}

CSS Nesting（ネスト記法）

従来：Sass/SCSSでしかネストできなかった

CSS Nestingの登場：ネイティブCSSでネスト可能に！

/* 従来のCSS */
.card { ... }
.card .title { ... }
.card .title:hover { ... }
.card.featured { ... }

/* CSS Nesting（新機能） */
.card {
  ...

  .title {
    ...

    &:hover {
      ...
    }
  }

  &.featured {
    ...
  }
}
