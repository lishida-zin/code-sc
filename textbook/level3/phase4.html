Server Components

Server ComponentsはReact 18で導入された革新的な機能です。 コンポーネントを「サーバーで実行」することで、バンドルサイズ削減とパフォーマンス向上を実現します。

Server Components vs Client Components

2026年のReact = Server Components + Client Components

Next.js App Routerでは、デフォルトがServer Componentです。

項目 Server Components Client Components
実行場所 サーバーのみ ブラウザ（+サーバーでSSR）
JSバンドル 含まれない（軽量） 含まれる
DB/ファイルアクセス 直接可能 不可（API経由のみ）
useState/useEffect 使用不可 使用可能
イベントハンドラ 使用不可 使用可能

Server/Client境界（図解）

コンポーネントツリーの中で、どこがサーバーで実行され、どこがブラウザで実行されるかを理解しましょう。

"use client" ディレクティブ

"use client"はClient Componentを宣言するためのディレクティブです。

Server Component（デフォルト）
// app/users/page.tsx
// "use client" がない = Server Component

async function UsersPage() {
  // サーバーでDB直アクセス可能
  const users = await db.query('SELECT * FROM users');

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
Client Component
'use client'; // ← ファイルの先頭に宣言

import { useState } from 'react';

function Counter() {
  // useStateが使える
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count}
    </button>
  );
}

レビューで指摘すべきポイント

データフェッチング

2026年のデータフェッチングは大きく変わりました。 useEffect内でのfetchは「古いパターン」です。 Server ComponentsとTanStack Queryを使い分けましょう。

Server Componentsでのfetch（推奨）

Server Componentでは、async/awaitで直接fetchできます。

Server Componentでのデータ取得
// app/posts/page.tsx (Server Component)
async function PostsPage() {
  // Server Componentでは直接fetchできる
  const response = await fetch('https://api.example.com/posts', {
    next: { revalidate: 3600 } // 1時間キャッシュ
  });
  const posts = await response.json();

  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

メリット：

  • ローディング状態の管理が不要
  • 自動的にキャッシュされる
  • クライアントJSバンドルに含まれない

TanStack Query（Client Component向け）

TanStack Query（旧React Query）は、Client Componentでのデータフェッチに最適なライブラリです。

TanStack Queryの基本的な使い方
'use client';

import { useQuery } from '@tanstack/react-query';

function UserProfile({ userId }: { userId: string }) {
  const { data, isLoading, error } = useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetch(`/api/users/${userId}`).then(res => res.json()),
  });

  if (isLoading) return <p>読み込み中...</p>;
  if (error) return <p>エラーが発生しました</p>;

  return <p>{data.name}</p>;
}

TanStack Queryの利点：

  • キャッシュ管理の自動化
  • バックグラウンド再フェッチ
  • ローディング・エラー状態の統一管理
  • 楽観的更新（Optimistic Updates）

古いパターン：useEffect内でfetch

2022年以前のパターン（非推奨）
'use client';

// ❌ 古いパターン（問題が多い）
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let isMounted = true;
    setLoading(true);

    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (isMounted) setUser(data);
      })
      .catch(err => {
        if (isMounted) setError(err);
      })
      .finally(() => {
        if (isMounted) setLoading(false);

  // ... 30行以上のボイラープレート

  • ボイラープレートが多い
  • キャッシュ管理がない

状態管理選択

2026年の状態管理は「適材適所」が重要です。 Redux一強の時代は終わり、用途に応じたライブラリを選択します。

状態管理の選択フローチャート（図解）

Zustand（シンプルな状態管理）

Zustandは、最小限のAPI、最小限のボイラープレートで状態管理ができるライブラリです。

Zustandの基本的な使い方
import { create } from 'zustand';

// ストアを作成
interface CounterStore {
  count: number;
  increment: () => void;
  decrement: () => void;
}

const useCounterStore = create<CounterStore>((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
}));

// コンポーネントで使用
function Counter() {
  const { count, increment, decrement } = useCounterStore();

  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+</button>
      <button onClick={decrement}>-</button>
    </div>
  );
}

Zustandの特徴：

  • Providerが不要（Contextのラップなし）
  • TypeScriptと相性が良い
  • バンドルサイズが小さい（約1KB）

Jotai（atom単位の状態管理）

Jotaiは、atomという最小単位で状態を管理します。Recoilに似た思想です。

Jotaiの基本的な使い方
import { atom, useAtom } from 'jotai';

// atomを定義
const countAtom = atom(0);
const doubledAtom = atom((get) => get(countAtom) * 2); // 派生atom

// コンポーネントで使用
function Counter() {
  const [count, setCount] = useAtom(countAtom);
  const [doubled] = useAtom(doubledAtom);

  return (
    <div>
      <p>Count: {count}</p>
      <p>Doubled: {doubled}</p>
      <button onClick={() => setCount(c => c + 1)}>+</button>
    </div>
  );
}

Jotaiの特徴：

  • atom単位で状態を分割（細かい再レンダリング制御）
  • 派生状態（computed）が簡単
  • 非同期atomのサポート

Contextの注意点

高頻度更新にContextは不向きです。

Contextの問題
// ❌ 高頻度更新をContextで管理
const MousePositionContext = createContext({ x: 0, y: 0 });

function App() {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  useEffect(() => {
    const handler = (e) => setPosition({ x: e.clientX, y: e.clientY });
    window.addEventListener('mousemove', handler);
    return () => window.removeEventListener('mousemove', handler);
  }, []);

  return (
    <MousePositionContext.Provider value={position}>
      {/* 全ての子コンポーネントが毎フレーム再レンダリング！ */}
      <App />
    </MousePositionContext.Provider>
  );
}

Contextが適している場面：

  • テーマ（ライト/ダーク）
  • 認証状態（ログインユーザー情報）
  • ロケール（言語設定）

→ 変更頻度が低いデータに最適

フォーム管理

フォーム管理はReact Hook Formが標準です。 Next.jsではServer Actionsも選択肢に加わりました。

React Hook Form

React Hook Formは、パフォーマンスに優れたフォーム管理ライブラリです。

React Hook Formの基本
'use client';

import { useForm } from 'react-hook-form';

interface LoginForm {
  email: string;
  password: string;
}

function LoginPage() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting }
  } = useForm<LoginForm>();

  const onSubmit = async (data: LoginForm) => {
    // サーバーに送信
    await fetch('/api/login', {
      method: 'POST',
      body: JSON.stringify(data),
    });
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <div>
        <input
          {...register('email', {
            required: 'メールアドレスは必須です',
            pattern: {
              value: /^[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}$/i,
              message: '有効なメールアドレスを入力してください'
            }
          })}
          placeholder="メールアドレス"
        />
        {errors.email && <span>{errors.email.message}</span>}
      </div>

      <div>
        <input
          type="password"
          {...register('password', {
            required: 'パスワードは必須です',
            minLength: { value: 8, message: '8文字以上必要です' }
          })}
          placeholder="パスワード"
        />
        {errors.password && <span>{errors.password.message}</span>}
      </div>

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? '送信中...' : 'ログイン'}
      </button>
    </form>
  );
}

React Hook Formの利点：

  • 非制御コンポーネントベースで高パフォーマンス
  • TypeScriptと相性が良い
  • バリデーション（Zod連携も可）
  • 再レンダリングを最小化

Server Actions（Next.js）

Server Actionsは、フォーム送信をサーバーで直接処理する機能です。

Server Actionsの例
// app/actions.ts
'use server';

export async function createUser(formData: FormData) {
  const name = formData.get('name') as string;
  const email = formData.get('email') as string;

  // サーバーでDB操作
  await db.user.create({ data: { name, email } });

  // リダイレクトやrevalidate
  revalidatePath('/users');
}

// app/new-user/page.tsx
import { createUser } from './actions';

function NewUserPage() {
  return (
    <form action={createUser}>
      <input name="name" placeholder="名前" required />
      <input name="email" type="email" placeholder="メール" required />
      <button type="submit">作成</button>
    </form>
  );
}

Server Actionsの利点：

  • クライアントJSなしでフォーム送信
  • プログレッシブエンハンスメント（JS無効でも動作）
  • サーバー関数を直接呼び出せる

Error Boundary

Error Boundaryは、コンポーネントツリー内のJavaScriptエラーをキャッチし、 フォールバックUIを表示する仕組みです。

Error Boundaryとは

問題：コンポーネント内でエラーが発生すると、アプリ全体が壊れる

エラーが発生するコンポーネント
function BuggyComponent() {
  // このエラーで画面全体が真っ白に...
  throw new Error('何かがおかしい！');
  return <div>正常</div>;
}

解決：Error Boundaryでエラーをキャッチし、フォールバックUIを表示

Error Boundaryでラップ
<ErrorBoundary fallback={<p>エラーが発生しました</p>}>
  <BuggyComponent />
</ErrorBoundary>

{/* BuggyComponentがエラーを出しても、
    他の部分は正常に表示される */}

クラスコンポーネントでの実装

Error Boundaryはクラスコンポーネントでのみ実装できます（Hooksでは不可）。

Error Boundaryの実装
import { Component, ReactNode } from 'react';

interface Props {
  children: ReactNode;
  fallback: ReactNode;
}

interface State {
  hasError: boolean;
}

class ErrorBoundary extends Component<Props, State> {
  constructor(props: Props) {
    super(props);
    this.state = { hasError: false };
  }

  // エラー発生時に呼ばれる
  static getDerivedStateFromError(_: Error): State {
    return { hasError: true };
  }

  // エラーログを記録
  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error('Error:', error, errorInfo);
    // エラー監視サービスに送信
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback;
    }
    return this.props.children;
  }
}

react-error-boundary ライブラリ

実務ではreact-error-boundaryライブラリを使うのが一般的です。

react-error-boundaryの使用例
import { ErrorBoundary } from 'react-error-boundary';

function ErrorFallback({ error, resetErrorBoundary }) {
  return (
    <div role="alert">
      <p>エラーが発生しました：</p>
      <pre>{error.message}</pre>
      <button onClick={resetErrorBoundary}>再試行</button>
    </div>
  );
}

function App() {
  return (
    <ErrorBoundary
      FallbackComponent={ErrorFallback}
      onReset={() => {
        // 状態をリセット
      }}
    >
      <MyComponent />
    </ErrorBoundary>
  );
}

利点：

  • リセット機能が組み込み
  • エラー情報をフォールバックに渡せる
  • useErrorBoundary Hooksも提供

レビューで指摘すべきポイント

  • Error Boundaryなし → 「エラー時のフォールバックUIを用意すべき」
  • アプリ全体を1つでラップ → 「機能単位で分割して影響範囲を限定すべき」
  • エラーログなし → 「監視サービスへの送信を検討」

パフォーマンス最適化

パフォーマンス問題を発見・解決するためのツールと手法を学びます。 React DevToolsが必須ツールです。

React DevToolsの使い方

React DevToolsはChrome/Firefox拡張機能で、Reactアプリのデバッグに必須です。

主な機能：

  • Componentsタブ：コンポーネントツリーの確認、Props/Stateの検査
  • Profilerタブ：レンダリングのパフォーマンス計測
Profilerでの計測手順
1. DevToolsのProfilerタブを開く
2. 「Record」ボタンをクリック
3. アプリを操作
4. 「Stop」をクリック
5. 各コンポーネントのレンダリング時間を確認

確認すべきポイント：
- 頻繁にレンダリングされるコンポーネント
- レンダリングに時間がかかるコンポーネント

React Compiler（2026年）

React Compiler（旧React Forget）が正式リリースされ、 メモ化を自動的に行うようになりました。

React Compilerの効果
// 手動メモ化が不要に
// Before: useMemo/useCallbackを手書き
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
const memoizedCallback = useCallback(() => doSomething(a, b), [a, b]);

// After: React Compilerが自動でメモ化

テスト

ReactコンポーネントのテストにはTesting Libraryを使います。 「ユーザー視点」でテストを書くのがポイントです。

Testing Library

Testing Libraryは、「実装の詳細ではなく、ユーザーの行動をテストする」という思想のライブラリです。

基本的なテストの書き方
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Counter from './Counter';

describe('Counter', () => {
  test('初期値が0で表示される', () => {
    render(<Counter />);

    // ユーザーに見えるテキストで要素を取得
    expect(screen.getByText('Count: 0')).toBeInTheDocument();
  });

  test('ボタンをクリックするとカウントが増える', async () => {
    const user = userEvent.setup();
    render(<Counter />);

    // ユーザーの操作をシミュレート
    await user.click(screen.getByRole('button', { name: '+' }));

    expect(screen.getByText('Count: 1')).toBeInTheDocument();
  });
});

userEvent（ユーザー操作のシミュレーション）

userEventは、実際のユーザー操作をより現実的にシミュレートします。

userEventの使い方
import userEvent from '@testing-library/user-event';

test('フォーム入力と送信', async () => {
  const user = userEvent.setup();
  const onSubmit = vi.fn();

  render(<LoginForm onSubmit={onSubmit} />);

  // テキスト入力
  await user.type(
    screen.getByLabelText('メールアドレス'),
    'test@example.com'
  );

  // パスワード入力
  await user.type(
    screen.getByLabelText('パスワード'),
    'password123'
  );

  // ボタンクリック
  await user.click(screen.getByRole('button', { name: 'ログイン' }));

  // コールバックが呼ばれたか確認
  expect(onSubmit).toHaveBeenCalledWith({
    email: 'test@example.com',
    password: 'password123'
  });
});

fireEventとの違い：

  • fireEvent：単一のイベントを発火（低レベル）
  • userEvent：実際のユーザー操作をシミュレート（高レベル、推奨）

モック（Mock）

モックは、テスト対象の依存関係を偽物に置き換える手法です。

API呼び出しのモック
import { vi } from 'vitest';

// fetchをモック
global.fetch = vi.fn();

test('データ取得成功時にリストが表示される', async () => {
  // モックの戻り値を設定
  (fetch as Mock).mockResolvedValue({
    json: () => Promise.resolve([
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' },
    ]),
  });

  render(<UserList />);

  // 非同期でデータが表示されるのを待つ
  expect(await screen.findByText('Alice')).toBeInTheDocument();
  expect(screen.getByText('Bob')).toBeInTheDocument();
});

モックすべきもの：

  • API呼び出し（fetch, axios）
  • 外部ライブラリ
  • ブラウザAPI（localStorage, window.location）

  }, []);

  // 問題4: key={index}
  return (
    <div>
      <h1>{user?.name}</h1>
      <ul>
        {posts.map((post, index) => (
          <li key={index}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}

問題点の解説

問題 指摘内容 修正方法
1. 依存配列が空 userIdが変わってもデータが更新されない [userId]を依存配列に追加
2. configオブジェクト 毎回新しい参照で無限ループ useMemoでconfigをメモ化、またはプリミティブ値を依存に
3. クリーンアップなし スクロールリスナーが蓄積（メモリリーク） return文でremoveEventListener
4. key={index} リストの並び替え・削除で予期しない動作 key={post.id}を使用

修正後のコード

正しいコード
'use client';

import { useState, useEffect, useMemo, useCallback } from 'react';

function UserDashboard({ userId }: { userId: string }) {
  const [user, setUser] = useState<User | null>(null);
  const [posts, setPosts] = useState<Post[]>([]);

  // 修正1: userIdを依存配列に
  useEffect(() => {
    let isMounted = true;
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (isMounted) setUser(data);
      });
    return () => { isMounted = false; };
  }, [userId]);

  // 修正2: configをuseMemoでメモ化
  const config = useMemo(() => ({ sortBy: 'date', limit: 10 }), []);
  useEffect(() => {
    fetch(`/api/posts?sort=${config.sortBy}&limit=${config.limit}`)
      .then(res => res.json())
      .then(setPosts);
  }, [config]);

  // 修正3: クリーンアップを追加
  useEffect(() => {
    const handleScroll = () => console.log('scrolled');
    window.addEventListener('scroll', handleScroll);
    return () => window.removeEventListener('scroll', handleScroll);
  }, []);

  // 修正4: 一意のIDをkeyに
  return (
    <div>
      <h1>{user?.name}</h1>
      <ul>
        {posts.map(post => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}
