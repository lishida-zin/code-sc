JavaScriptに「型」を追加した言語

TypeScriptはJavaScriptのスーパーセットです。

「スーパーセット」とは、JavaScriptの機能をすべて含み、
さらに「型」という機能を追加したものです。

🏠 たとえ話

JavaScript = 普通の家
TypeScript = セキュリティシステム付きの家

セキュリティ（型チェック）があると、
「泥棒（バグ）」が入りにくくなります。

型とは何か？

「型」とは、データの種類のことです。

JavaScript（型なし）
// 何でも入る（危険）
let name = "田中";
name = 123;  // エラーにならない！

// 実行時に壊れる
console.log(name.toUpperCase());
// TypeError: toUpperCase is not a function
TypeScript（型あり）
// 文字列だけ入る（安全）
let name: string = "田中";
name = 123;  // コンパイルエラー！

// 実行前にミスが分かる

コンパイル時チェック

TypeScriptはコードを実行する前にエラーを見つけます。

✓ コンパイル時チェックの恩恵
  • 早期発見: 書いた瞬間にエラーが分かる
  • 自動補完: IDEが賢くなる
  • リファクタリング安全: 変更の影響が分かる
  • ドキュメント: 型が仕様を語る

2026年、TypeScriptは必須

2026年現在、新規プロジェクトのほとんどがTypeScriptです。

  • React/Next.js → TypeScript推奨
  • Vue/Nuxt → TypeScript推奨
  • Node.js → TypeScript利用が一般的

AIが書くコードも多くがTypeScriptです。
型を読めないと、コードレビューができません。

プリミティブ型

TypeScriptの基本的な型は3つです。

📦 基本の3型 
// 文字列
const name: string = "田中";

// 数値（整数も小数も同じ）
const age: number = 25;
const price: number = 1980.5;

// 真偽値
const isActive: boolean = true;

null と undefined

「値がない」ことを表す型が2つあります。

undefined

「まだ値が設定されていない」

let user: string | undefined;
console.log(user); // undefined

// 変数を宣言しただけの状態
null

「意図的に空にした」

let user: string | null = null;
console.log(user); // null

// 明示的に「なし」と設定

any の危険性

anyは「どんな型でもOK」という意味です。

🔥 any = 型チェック放棄 
// ❌ any を使うと型チェックが無効化
function process(data: any) {
  // 何をしてもエラーにならない
  return data.name.toUpperCase();
}

process(123); // 実行時エラー！
// TypeError: Cannot read property 'toUpperCase' of undefined

anyはTypeScriptの恩恵を捨てることを意味します。
レビューで見つけたら、必ず指摘しましょう。

❌ anyの乱用
function getUser(id: any): any {
  // 何が入って何が出るか不明
}

const result: any = getUser("abc");
result.name.first; // 実行時まで分からない
✓ 具体的な型
interface User {
  name: string;
  age: number;
}

function getUser(id: string): User {
  // 入力と出力が明確
}

const result = getUser("abc");
result.name; // 自動補完が効く

配列の型

配列の型は2つの書き方があります。 

// 書き方1: type[]
const numbers: number[] = [1, 2, 3];
const names: string[] = ["田中", "山田"];

// 書き方2: Array<type>
const numbers2: Array<number> = [1, 2, 3];
const names2: Array<string> = ["田中", "山田"];

// 両方とも同じ意味

型推論

📚 このページで学ぶこと
  • 型推論の仕組み
  • 明示的型注釈との違い
  • いつ型注釈が必要か

TypeScriptは賢い

TypeScriptは値から型を推測できます。 

// 型注釈なしでも型が付く
const name = "田中";   // string と推論
const age = 25;        // number と推論
const isActive = true; // boolean と推論

// 型注釈を書いたのと同じ効果
// const name: string = "田中";

これを型推論（Type Inference）と呼びます。

型推論 vs 明示的型注釈

型推論（暗黙）
// コンパイラが自動で型を付ける
const user = {
  name: "田中",
  age: 25
};
// { name: string; age: number } と推論

✓ コードが簡潔

型注釈（明示）
// 開発者が明示的に型を書く
const user: {
  name: string;
  age: number;
} = {
  name: "田中",
  age: 25
};

✓ 意図が明確

型注釈が必要な場面

型推論に頼れない場面があります。

⚠️ 型注釈が必要なケース
  • 関数の引数: 推論できない
  • 空の配列: any[]になってしまう
  • API の戻り値: 型が不明
  • 意図を明示したい: 可読性のため
❌ 型注釈なし
// 引数の型が不明
function greet(name) {
  return "Hello, " + name;
}

// 何でも渡せてしまう
greet(123); // エラーにならない
✓ 型注釈あり
// 引数の型が明確
function greet(name: string) {
  return "Hello, " + name;
}

// 間違いがすぐ分かる
greet(123); // コンパイルエラー

関数の戻り値の型推論

関数の戻り値は推論されることが多いです。 

// 戻り値は string と推論される
function greet(name: string) {
  return "Hello, " + name;
}

// 戻り値は number と推論される
function add(a: number, b: number) {
  return a + b;
}

// 明示的に書くこともできる
function greet(name: string): string {
  return "Hello, " + name;
}
💡 実務でのルール

多くのプロジェクトでは関数の引数は必須、
戻り値は省略OKというルールを採用しています。

Union型・リテラル型

📚 このページで学ぶこと
  • Union型（複数の型を許容）
  • リテラル型（特定の値のみ許容）
  • 型の絞り込み

Union型とは

Union型は「AまたはB」という型です。 

// string または number
let value: string | number;

value = "hello";  // OK
value = 123;      // OK
value = true;     // エラー！boolean は許可されていない

|（パイプ）で型を繋げます。

よく使うUnion型

// nullを許容する型（Nullable）
let user: User | null = null;

// undefinedを許容する型（Optional）
let name: string | undefined;

// 複数の型を許容
function format(value: string | number | boolean): string {
  return String(value);
}

リテラル型とは

リテラル型は「特定の値のみ」を許容する型です。 

// "success" または "error" のみ許容
type Status = "success" | "error" | "pending";

let status: Status;
status = "success";  // OK
status = "error";    // OK
status = "complete"; // エラー！許可されていない値
✓ リテラル型のメリット
  • タイポ防止: 間違った文字列を書けない
  • 自動補完: IDEが候補を出してくれる
  • 意図が明確: 取りうる値が分かる

型の絞り込み（Narrowing）

Union型を使うと、実行時にどの型か判断が必要です。 

function printId(id: string | number) {
  // この時点では string か number か不明

  if (typeof id === "string") {
    // ここでは string と確定
    console.log(id.toUpperCase());
  } else {
    // ここでは number と確定
    console.log(id.toFixed(2));
  }
}

typeofで型をチェックすると、
TypeScriptは自動的に型を絞り込みます。

interface と type

📚 このページで学ぶこと
  • interfaceの書き方
  • typeの書き方
  • 使い分けの基準

interfaceとは

interfaceはオブジェクトの形を定義します。 

// Userオブジェクトの形を定義
interface User {
  name: string;
  age: number;
  email?: string;  // ?は省略可能
}

// この形に従うオブジェクト
const user: User = {
  name: "田中",
  age: 25
  // emailは省略OK
};

typeとは

typeは型に別名を付けます。 

// オブジェクトの形を定義（interfaceと同様）
type User = {
  name: string;
  age: number;
  email?: string;
};

// Union型やリテラル型にも使える
type Status = "success" | "error" | "pending";
type ID = string | number;

interface vs type

interface
// 宣言のマージ（拡張）ができる
interface User {
  name: string;
}
interface User {
  age: number;
}
// { name: string; age: number } になる

// extendsで継承
interface Admin extends User {
  role: string;
}
type
// Union型が作れる
type ID = string | number;

// リテラル型が作れる
type Status = "ok" | "ng";

// 交差型で合成
type Admin = User & {
  role: string;
};

使い分けの基準

💡 実務でのルール
  • オブジェクトの形 → interface
  • Union型、リテラル型 → type
  • 迷ったら → interface

多くのプロジェクトでは「基本はinterface、必要ならtype」です。

読み取り専用（readonly）

プロパティを変更不可にできます。 

interface User {
  readonly id: string;  // 変更不可
  name: string;         // 変更可能
}

const user: User = {
  id: "abc123",
  name: "田中"
};

user.name = "山田";  // OK
user.id = "xyz";     // エラー！readonlyは変更不可

ジェネリクス

ジェネリクスとは

ジェネリクスは「型の引数」です。

🏠 たとえ話

関数に値の引数があるように、
型にも型の引数があります。 

// 値の引数
function greet(name: string) { ... }
greet("田中");  // 引数に値を渡す

// 型の引数（ジェネリクス）
function identity<T>(value: T): T { ... }
identity<string>("hello");  // 引数に型を渡す

Array<T>の読み方

Array<T>は「T型の配列」という意味です。 

// T = string の場合
const names: Array<string> = ["田中", "山田"];
// string[] と同じ意味

// T = number の場合
const ages: Array<number> = [25, 30, 35];
// number[] と同じ意味

// T = User の場合
const users: Array<User> = [
  { name: "田中", age: 25 },
  { name: "山田", age: 30 }
];
// User[] と同じ意味

Promise<T>の読み方

Promise<T>は「T型を返す非同期処理」です。 

// string を返すPromise
async function fetchName(): Promise<string> {
  return "田中";
}

// User を返すPromise
async function fetchUser(): Promise<User> {
  return { name: "田中", age: 25 };
}

// 配列を返すPromise
async function fetchUsers(): Promise<User[]> {
  return [
    { name: "田中", age: 25 },
    { name: "山田", age: 30 }
  ];
}

関数のジェネリクス

自分でジェネリクスを使った関数も作れます。 

// T は型のプレースホルダー
function first<T>(items: T[]): T | undefined {
  return items[0];
}

// 使うとき、T が自動的に決まる
const num = first([1, 2, 3]);     // T = number
const str = first(["a", "b"]);   // T = string

// 明示的に指定もできる
const num2 = first<number>([1, 2, 3]);
💡 読めればOK

ジェネリクスを自分で書くことは少ないです。
ライブラリのコードを読めることが重要です。

型ガードとは

型ガードは、型を安全に絞り込む方法です。 

function process(value: string | number) {
  // この時点では string か number か不明

  // 型ガード: typeof でチェック
  if (typeof value === "string") {
    // ここでは value は string と確定
    console.log(value.toUpperCase());
  } else {
    // ここでは value は number と確定
    console.log(value.toFixed(2));
  }
}

typeofによる型ガード

typeofはプリミティブ型の判定に使います。 

function format(value: string | number | boolean) {
  if (typeof value === "string") {
    return value.toUpperCase();
  }
  if (typeof value === "number") {
    return value.toFixed(2);
  }
  // ここでは boolean と確定
  return value ? "Yes" : "No";
}

// typeof で判定できる型
// "string" | "number" | "boolean" | "undefined"
// "object" | "function" | "symbol" | "bigint"

instanceofによる型ガード

instanceofはクラスのインスタンス判定に使います。 

class Dog {
  bark() { console.log("ワン！"); }
}

class Cat {
  meow() { console.log("ニャー"); }
}

function speak(animal: Dog | Cat) {
  if (animal instanceof Dog) {
    // ここでは Dog と確定
    animal.bark();
  } else {
    // ここでは Cat と確定
    animal.meow();
  }
}

in演算子による型ガード

inはプロパティの存在確認に使います。 

interface Bird {
  fly(): void;
}

interface Fish {
  swim(): void;
}

function move(animal: Bird | Fish) {
  if ("fly" in animal) {
    // fly プロパティがあれば Bird
    animal.fly();
  } else {
    // なければ Fish
    animal.swim();
  }
}

asアサーションの危険性

🔥 asは「嘘をつく」可能性 
// ❌ 危険な型アサーション
const element = document.getElementById("app") as HTMLDivElement;
element.innerHTML = "Hello";  // nullなら実行時エラー！

// ✓ 安全な型ガード
const element = document.getElementById("app");
if (element instanceof HTMLDivElement) {
  element.innerHTML = "Hello";  // 安全
}

asを使うと型チェックを「スキップ」します。
レビューで見つけたら、型ガードで書き直すべきか検討しましょう。

ユーティリティ型とは

TypeScriptには便利な組み込み型があります。

既存の型を変換して新しい型を作れます。

Partial<T>

すべてのプロパティを省略可能にします。 

interface User {
  name: string;
  age: number;
  email: string;
}

// すべて省略可能になる
type PartialUser = Partial<User>;
// {
//   name?: string;
//   age?: number;
//   email?: string;
// }

// 更新処理でよく使う
function updateUser(id: string, data: Partial<User>) {
  // 一部のプロパティだけ更新できる
}

updateUser("123", { name: "田中" }); // OK

Required<T>

すべてのプロパティを必須にします。 

interface Config {
  debug?: boolean;
  timeout?: number;
}

// すべて必須になる
type RequiredConfig = Required<Config>;
// {
//   debug: boolean;
//   timeout: number;
// }

Pick<T, K>

指定したプロパティだけ抽出します。 

interface User {
  id: string;
  name: string;
  age: number;
  email: string;
}

// name と email だけ抽出
type UserContact = Pick<User, "name" | "email">;
// {
//   name: string;
//   email: string;
// }

Omit<T, K>

指定したプロパティを除外します。 

interface User {
  id: string;
  name: string;
  age: number;
  password: string;
}

// password を除外
type PublicUser = Omit<User, "password">;
// {
//   id: string;
//   name: string;
//   age: number;
// }

// APIレスポンスで機密情報を除く時に便利

Record<K, V>

キーと値の型を指定したオブジェクト型を作ります。 

// キーがstring、値がnumberのオブジェクト
type Scores = Record<string, number>;

const scores: Scores = {
  math: 90,
  english: 85,
  science: 92
};

// キーをリテラル型で限定
type StatusColors = Record<"success" | "error" | "warning", string>;

const colors: StatusColors = {
  success: "green",
  error: "red",
  warning: "orange"
};

まとめ：よく使うユーティリティ型

✓ 覚えておくべき5つ
  • Partial<T>: すべて省略可能に
  • Required<T>: すべて必須に
  • Pick<T, K>: 指定プロパティを抽出
  • Omit<T, K>: 指定プロパティを除外
  • Record<K, V>: キーと値の型を指定
