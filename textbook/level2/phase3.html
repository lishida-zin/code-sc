16. 同期と非同期

🎯 このレッスンで読めるようになること
  • 同期処理と非同期処理の違いがわかる
  • なぜ非同期処理が必要なのか説明できる
  • ブロッキングとノンブロッキングを理解できる

同期処理とは？

同期処理（Synchronous）とは、
「上から順番に、1つずつ実行する」処理方式です。

🍳 たとえ話：料理で考える

同期処理 = 1品ずつ作る

  1. ご飯を炊く（10分待つ）
  2. 炊き終わったら味噌汁を作る（5分待つ）
  3. 作り終わったら焼き魚を焼く（7分待つ）

合計：22分かかる 

// 同期処理のコード例
console.log('1番目');
console.log('2番目');
console.log('3番目');

// 出力:
// 1番目
// 2番目
// 3番目

同期処理では、前の行が完了するまで次の行に進みません。

非同期処理とは？

非同期処理（Asynchronous）とは、
「待っている間に、別の処理を進める」方式です。

🍳 たとえ話：効率的な料理

非同期処理 = 同時進行で作る

  1. ご飯を炊飯器にセット（待たない！）
  2. その間に味噌汁を作り始める
  3. 味噌汁を煮込む間に魚を焼き始める

合計：10分程度で完成！ 

// 非同期処理のコード例
console.log('1番目');

setTimeout(() => {
  console.log('2番目（1秒後）');
}, 1000);

console.log('3番目');

// 出力:
// 1番目
// 3番目      ← 先に出る！
// 2番目（1秒後）  ← 後から出る

なぜ非同期処理が必要？

ブラウザはシングルスレッド（1つの処理しかできない）です。
もし同期処理だけだと...

⚠️ 同期処理だけの問題点
  • サーバーからデータ取得中 → 画面がフリーズ
  • 大きなファイル読み込み中 → 操作不能
  • ユーザー体験が最悪になる

ブロッキングとノンブロッキング

用語 意味 例
ブロッキング 処理が終わるまで止まる 同期処理
ノンブロッキング 待たずに次に進む 非同期処理

JavaScriptの非同期処理の例

処理 用途
setTimeout 指定時間後に実行
fetch サーバーからデータ取得
addEventListener ユーザー操作を待つ
ファイル読み込み ファイルを読む

イベントループ（超重要）

JavaScriptが非同期処理を実現する仕組みがイベントループです。

🔄 イベントループの動き（簡略版）
  1. コールスタックで同期処理を実行
  2. 非同期処理はタスクキューに登録される
  3. コールスタックが空になったらキューから取り出して実行
console.log('1');        // → コールスタックで即実行

setTimeout(() => {
  console.log('2');      // → タスクキューに登録
}, 0);

console.log('3');        // → コールスタックで即実行

// 結果: 1 → 3 → 2
// 理由: 同期処理(1,3)が全部終わってからキュー(2)を実行
💡 覚えておくこと

「同期処理が全部終わってから、非同期処理が実行される」
これがJavaScript非同期処理の基本原則です。

クイズ：次のコードの出力順は？ 

console.log('A');
setTimeout(() => console.log('B'), 0);
console.log('C');
解説：setTimeoutは0ミリ秒でも非同期です。 JavaScriptは「同期処理をすべて終えてから非同期処理を実行」します。 だからA→C（同期）が先に出て、B（非同期）が最後になります。
📝 まとめ
  • 同期 = 上から順番に、1つずつ実行
  • 非同期 = 待っている間に別の処理を進める
  • イベントループが「同期→非同期」の順序を管理
  • UIをブロックしないために非同期処理は必須

🔴 よくある問題
問題 指摘例
重い処理を同期で実行 「非同期化してUIをブロックしないように」
非同期の順序を理解していない 「コールバックの実行順を確認」

17. コールバック

🎯 このレッスンで読めるようになること
  • コールバック関数とは何かを説明できる
  • コールバック地獄を識別できる
  • なぜPromiseが生まれたか理解できる

コールバック関数とは？

コールバック（Callback）とは、
「あとで呼び出してもらう関数」のことです。

📞 語源：Call Back = 折り返し電話

「処理が終わったら、この関数を呼んでね」と
事前に関数を渡しておく仕組みです。 

// コールバックの基本形
function doSomething(callback) {
  console.log('処理中...');
  callback();  // 処理後にコールバックを呼ぶ
}

// 使い方
doSomething(() => {
  console.log('終わったよ！');
});

// 出力:
// 処理中...
// 終わったよ！

非同期処理とコールバック

非同期処理では、「終わったら何をするか」を
コールバックで指定します。 

// setTimeout のコールバック
setTimeout(() => {
  console.log('1秒経ちました');
}, 1000);

// addEventListener のコールバック
button.addEventListener('click', () => {
  console.log('クリックされました');
});

コールバック地獄（Callback Hell）

非同期処理を連続で行うと、
コールバックが入れ子になって読みにくくなります。 

// ❌ コールバック地獄（読みにくい！）
getUser(userId, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetails(orders[0].id, (details) => {
      getPaymentInfo(details.paymentId, (payment) => {
        console.log(payment);
        // さらに深くなる...
      });
    });
  });
});
⚠️ コールバック地獄の問題点
  • 読みにくい - インデントが深くなる
  • 保守しにくい - 変更が困難
  • エラー処理が複雑 - 各階層で処理が必要

エラー処理の問題

// 各コールバックでエラー処理が必要
getUser(userId, (error, user) => {
  if (error) {
    console.error('ユーザー取得失敗');
    return;
  }
  getOrders(user.id, (error, orders) => {
    if (error) {
      console.error('注文取得失敗');
      return;
    }
    // さらに続く...
  });
});

この問題を解決するために、
Promiseが生まれました。

クイズ：コールバック地獄の最大の問題点は？

解説：コールバック地獄は実行速度やメモリには影響しません。 問題は「人間が読みにくい」こと。深いインデント、エラー処理の分散、 流れの追いにくさが保守を困難にします。

クイズ2：コールバック地獄を解消する現代的な方法は？

解説：Promise/async-awaitを使うと、ネストなしで 非同期処理を順番に書けます。これがES2015以降の標準的な方法です。
📝 まとめ
  • コールバック = 「あとで呼んでね」と渡す関数
  • 非同期処理の結果を受け取る古い方法
  • ネストが深くなるとコールバック地獄
  • この問題を解決するためにPromiseが生まれた

レビューで指摘すべきポイント

🔴 コールバック地獄を見つけたら

指摘：「3段以上のネストはPromise/async-awaitで書き直すべき」

18. Promise基礎

🎯 このレッスンで読めるようになること
  • Promiseとは何かを説明できる
  • then/catch/finallyの役割がわかる
  • Promiseの3つの状態を理解できる

Promiseとは？

Promise（プロミス）とは、
「非同期処理の結果を約束するオブジェクト」です。

📝 語源：Promise = 約束

「今は結果がないけど、あとで必ず結果を返すよ」
という約束を表すオブジェクトです。

Promiseの3つの状態

状態 意味 日本語
pending 処理中（まだ結果がない） 保留中
fulfilled 成功（結果が得られた） 成功
rejected 失敗（エラーが発生） 拒否
📦 たとえ話：通販の荷物追跡
  • pending = 配送中
  • fulfilled = 届いた！
  • rejected = 配送失敗...

Promiseの基本構文

// Promiseを作る
const promise = new Promise((resolve, reject) => {
  // 非同期処理
  const success = true;

  if (success) {
    resolve('成功しました');  // 成功時
  } else {
    reject('失敗しました');   // 失敗時
  }
});

// Promiseを使う
promise
  .then(result => {
    console.log(result);  // '成功しました'
  })
  .catch(error => {
    console.log(error);   // '失敗しました'
  });

then / catch / finally

メソッド 呼ばれるタイミング 用途
.then() 成功時（fulfilled） 結果を受け取る
.catch() 失敗時（rejected） エラーを処理
.finally() 成功でも失敗でも 後片付け 
fetch('/api/user')
  .then(response => {
    console.log('成功:', response);
  })
  .catch(error => {
    console.log('失敗:', error);
  })
  .finally(() => {
    console.log('ローディング終了');
  });

すぐにPromiseを作るショートカット

テストやシンプルな処理では、すぐに解決/拒否するPromiseが便利です。 

// すぐに成功するPromise
const success = Promise.resolve('成功！');
success.then(msg => console.log(msg));  // '成功！'

// すぐに失敗するPromise
const fail = Promise.reject('失敗...');
fail.catch(err => console.log(err));  // '失敗...'

// new Promiseを使わなくてOK
// これと同じ:
// new Promise(resolve => resolve('成功！'))

コールバック地獄との比較

// ❌ コールバック地獄
getUser(id, (user) => {
  getOrders(user.id, (orders) => {
    getDetails(orders[0].id, (details) => {
      console.log(details);
    });
  });
});

// ⭕ Promiseで書き直し
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getDetails(orders[0].id))
  .then(details => console.log(details))
  .catch(error => console.error(error));
📝 まとめ
  • Promiseは「あとで結果を返す約束」
  • 状態は pending → fulfilled or rejected
  • .then()で成功、.catch()で失敗を処理
  • .finally()は成功でも失敗でも実行

クイズ：Promiseの状態として存在しないのは？

解説：Promiseの状態はpending/fulfilled/rejectedの3つだけ。 「cancelled」は存在しません。実は標準のPromiseはキャンセルできません。 これはPromiseの設計上の制限として知られています。

🔴 よくある問題
問題 指摘例
.catch() がない 「エラーハンドリングを追加すべき」
Promiseを返さない 「return がないとチェーンが切れる」

19. Promiseチェーン

🎯 このレッスンで読めるようになること
  • Promiseチェーンの流れを追える
  • thenの戻り値がどう伝わるか理解できる
  • エラーがどこでキャッチされるか把握できる

Promiseチェーンとは？

.then()は新しいPromiseを返すので、
連続して繋げることができます。これがチェーンです。 

// 基本のチェーン
Promise.resolve(1)
  .then(x => x + 1)   // 2
  .then(x => x * 2)   // 4
  .then(x => console.log(x));  // 4

チェーンの流れを追う

🔗 チェーンのルール
  1. 前の.then()の戻り値が次の引数になる
  2. Promiseを返すと、それが解決されてから次に進む
  3. エラーが起きると.catch()までスキップ
// 実践的な例
fetch('/api/user')
  .then(response => response.json())   // JSONに変換
  .then(user => fetch(`/api/orders/${user.id}`))  // 次のリクエスト
  .then(response => response.json())
  .then(orders => console.log(orders))
  .catch(error => console.error(error));

よくある間違い：returnを忘れる

// ❌ return がない → undefined が渡る
fetch('/api/user')
  .then(response => {
    response.json();  // return がない！
  })
  .then(data => {
    console.log(data);  // undefined
  });

// ⭕ 正しい
fetch('/api/user')
  .then(response => {
    return response.json();  // return が必要
  })
  .then(data => {
    console.log(data);  // 正しいデータ
  });

// ⭕ アロー関数なら省略可
fetch('/api/user')
  .then(response => response.json())  // 暗黙のreturn
  .then(data => console.log(data));

エラーの伝播

// エラーは.catch()まで伝播する
Promise.resolve()
  .then(() => {
    throw new Error('エラー発生！');
  })
  .then(() => {
    console.log('ここは実行されない');
  })
  .then(() => {
    console.log('ここも実行されない');
  })
  .catch(error => {
    console.log('キャッチ:', error.message);
  });
💡 ポイント

エラーが発生すると、途中の.then()はすべてスキップされ、
最初の.catch()に到達します。

クイズ：次のコードの出力は？ 

Promise.resolve(10)
  .then(x => x * 2)
  .then(x => { x + 5; })  // ここに注目
  .then(x => console.log(x));
解説：{ x + 5; }は波括弧があるので、 returnがないと戻り値はundefinedになります。 x => x + 5（括弧なし）なら25ですが、 x => { x + 5; }（波括弧あり）は明示的なreturnが必要です。

クイズ2：Promiseチェーンでエラーが発生した場合、どこまで伝播する？

解説：Promiseチェーンでエラーが発生すると、 途中の.then()をスキップして.catch()まで一気に伝播します。 これがPromiseのエラー伝播の仕組みです。
📝 まとめ
  • .then()は新しいPromiseを返す → チェーン可能
  • 前の.then()の戻り値が次の引数になる
  • returnを忘れるとundefinedが伝わる（超重要）
  • エラーは.catch()までスキップして伝播

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
thenでreturn忘れ 「returnがないとundefinedが伝わる」
チェーンの途中でcatch 「catchの位置でエラー処理範囲が変わる」

20. async/await

🎯 このレッスンで読めるようになること
  • async/awaitの構文を読める
  • Promiseとの関係を理解できる
  • await忘れのバグを見抜ける
⚠️ 最重要セクション

async/awaitは2026年最もバグが多い領域です。
このセクションは特に集中して学んでください。

async/awaitとは？

async/awaitは、
「Promiseを同期処理のように書ける」構文です。 

// Promiseチェーン
fetch('/api/user')
  .then(response => response.json())
  .then(user => console.log(user));

// ⭕ async/await（同じ処理）
async function getUser() {
  const response = await fetch('/api/user');
  const user = await response.json();
  console.log(user);
}

async関数の特徴

📝 asyncのルール
  1. 関数の前にasyncをつける
  2. async関数は常にPromiseを返す
  3. async関数の中でだけawaitが使える
// async関数は常にPromiseを返す
async function hello() {
  return 'Hello';
}

// 以下と同じ
function hello() {
  return Promise.resolve('Hello');
}

// だから.then()で受け取れる
hello().then(msg => console.log(msg));  // 'Hello'

awaitの動作

awaitはPromiseが解決するまで待つキーワードです。 

async function example() {
  console.log('1. 開始');

  const result = await someAsyncTask();  // ここで一時停止

  console.log('2. 完了:', result);  // Promiseが解決してから実行
}

⚠️ 致命的バグ：await忘れ

🔴 最も多いバグ

awaitを忘れると、Promiseオブジェクト自体が変数に入ります。 

async function getUser() {
  // ❌ awaitを忘れた
  const user = fetchUser();
  console.log(user.name);  // undefined（userはPromise）

  // ⭕ 正しい
  const user = await fetchUser();
  console.log(user.name);  // "太郎"
}

⚠️ 致命的バグ：forEach + async

🔴 絶対に覚えるべきバグ

forEachの中でawaitを使っても待ってくれません。 

// ❌ forEachは待たない！
async function processItems(items) {
  items.forEach(async (item) => {
    await processItem(item);  // 待たない！
  });
  console.log('完了');  // 処理中に出力される
}

// ⭕ for...of を使う
async function processItems(items) {
  for (const item of items) {
    await processItem(item);  // ちゃんと待つ
  }
  console.log('完了');  // 全部終わってから出力
}

// ⭕ 並列で実行したいなら
async function processItems(items) {
  await Promise.all(items.map(item => processItem(item)));
  console.log('完了');
}

クイズ1：次のコードの問題点は？ 

async function getData() {
  const response = fetch('/api/data');
  const data = response.json();
  return data;
}
解説：fetch()も.json()も Promiseを返すので、両方にawaitが必要です。 awaitがないと、responseはPromiseオブジェクト、 Promise.json()はエラーになります。

クイズ2：配列の各要素を順番に処理したい。正しいのは？

解説：forEachはawaitを待ちません（コールバックを同期的に呼ぶだけ）。 for...ofならawaitが正しく動作します。 mapはPromise配列を返すだけで、awaitがありません。

クイズ3：async関数の戻り値は？ 

async function test() {
  return 42;
}
解説：async関数は常にPromiseを返します。 return 42はreturn Promise.resolve(42)と同じです。 だからtest().then(n => ...)で受け取ります。
📝 まとめ
  • async関数は常にPromiseを返す
  • awaitはPromiseが解決するまで待つ
  • await忘れ = Promiseオブジェクトがそのまま使われる（最頻出バグ）
  • forEach + async = 待たない（for...ofを使う）

レビューで指摘すべきポイント

🔴 最高危険度の問題
問題 指摘例 危険度
await忘れ 「awaitが必要。Promiseがそのまま使われている」 🔴最高
forEach + async 「forEachはawaitを待たない。for...ofを使うべき」 🔴最高

21. エラーハンドリング

🎯 このレッスンで読めるようになること
  • try/catch/finallyの使い方がわかる
  • 非同期処理でのエラー処理を理解できる
  • エラーハンドリング漏れを指摘できる

なぜエラーハンドリングが重要？

非同期処理は失敗する可能性が高いです。

⚠️ 失敗する原因
  • ネットワークエラー（サーバーに繋がらない）
  • タイムアウト（応答が遅い）
  • サーバーエラー（500エラー）
  • 認証エラー（ログイン切れ）

try/catch/finally

async function fetchData() {
  try {
    // 成功するかもしれない処理
    const response = await fetch('/api/data');
    const data = await response.json();
    return data;

  } catch (error) {
    // エラーが起きたら実行
    console.error('エラー:', error.message);
    return null;

  } finally {
    // 成功でも失敗でも必ず実行
    console.log('処理終了');
  }
}
ブロック 実行タイミング 用途
try 最初に実行 メイン処理
catch エラー時のみ エラー処理
finally 必ず最後に 後片付け

finallyの使いどころ

async function loadData() {
  const loading = document.getElementById('loading');
  loading.style.display = 'block';  // ローディング表示

  try {
    const data = await fetchData();
    displayData(data);
  } catch (error) {
    showError(error);
  } finally {
    // 成功でも失敗でもローディングを消す
    loading.style.display = 'none';
  }
}

❌ よくある間違い

// ❌ try/catch がない
async function getData() {
  const response = await fetch('/api/data');  // エラーで落ちる
  return response.json();
}

// ❌ catchで何もしない
async function getData() {
  try {
    const response = await fetch('/api/data');
    return response.json();
  } catch (error) {
    // 何もしない → 問題が隠れる
  }
}

// ⭕ 適切なエラー処理
async function getData() {
  try {
    const response = await fetch('/api/data');
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    return response.json();
  } catch (error) {
    console.error('データ取得失敗:', error);
    throw error;  // 上位に伝播させる or 代替値を返す
  }
}

エラーの再スロー

async function processData() {
  try {
    const data = await fetchData();
    return transform(data);
  } catch (error) {
    // ログを残して再スロー
    console.error('processData failed:', error);
    throw error;  // 呼び出し元でも処理できる
  }
}

errorオブジェクトの構造

catchで受け取るerrorには便利なプロパティがあります。

プロパティ 内容 例
error.message エラーメッセージ "Failed to fetch"
error.name エラーの種類 "TypeError"
error.stack 発生場所の追跡情報 デバッグ用 
try {
  await fetch('/api/data');
} catch (error) {
  console.log(error.name);     // "TypeError"
  console.log(error.message);  // "Failed to fetch"
  console.log(error.stack);    // 詳細なスタックトレース
}
📝 まとめ
  • tryで危険な処理を囲む
  • catchでエラーを適切に処理（握り潰さない）
  • finallyでクリーンアップ（ローディング解除など）
  • 必要に応じてthrowで再スロー

クイズ：finallyブロックが実行されるのは？

解説：finallyは「最終的に」という意味。 tryが成功してもcatchが実行されても、必ず最後に実行されます。 ローディング表示の解除やリソースの解放に使います。

クイズ2：このコードの問題点は？ 

try {
  const data = await fetchData();
} catch (error) {
  // 何もしない
}

解説：catchで何もしないと、エラーが「握り潰され」ます。 バグの原因がわからなくなるため、最低限console.errorでログ出力するか、 必要に応じてthrowで再スローすべきです。

レビューで指摘すべきポイント

🔍 コードレビューの観点
  • async/await エラーハンドリング漏れ：awaitする呼び出しにtry/catchがないとエラーが握り潰されるか、未処理Promiseエラーになる
  • catchブロックの空実装：catch(e) {}はエラーを隠す最悪のパターン。最低限ログ出力か再スローすべき
  • response.okの未チェック：fetchは404/500でもrejectしない。response.okのチェックが必須

22. 並列・直列実行

🎯 このレッスンで読めるようになること
  • Promise.all / allSettled / race を読める
  • 並列と直列の違いを理解できる
  • 不要な直列実行を指摘できる

直列 vs 並列

🍳 たとえ話：朝食を作る

直列 = トースト焼く → 卵焼く → コーヒー淹れる（順番に）
並列 = 3つ同時に進行！ 

// ❌ 直列（遅い）- 1つずつ待つ
async function slow() {
  const user = await fetchUser();      // 1秒
  const orders = await fetchOrders();  // 1秒
  const products = await fetchProducts(); // 1秒
  // 合計: 3秒
}

// ⭕ 並列（速い）- 同時に実行
async function fast() {
  const [user, orders, products] = await Promise.all([
    fetchUser(),      // 同時に開始
    fetchOrders(),    // 同時に開始
    fetchProducts()   // 同時に開始
  ]);
  // 合計: 1秒（最も遅い処理の時間）
}

Promise.all

すべてのPromiseが成功したら、結果の配列を返します。
1つでも失敗したら、即座にrejectされます。 

// 全部成功 → 結果の配列
const results = await Promise.all([
  Promise.resolve(1),
  Promise.resolve(2),
  Promise.resolve(3)
]);
console.log(results);  // [1, 2, 3]

// 1つでも失敗 → 即座にエラー
await Promise.all([
  Promise.resolve(1),
  Promise.reject('失敗'),
  Promise.resolve(3)
]);  // Error: 失敗

Promise.allSettled

すべてのPromiseが完了するまで待ちます。
成功・失敗の両方の結果を取得できます。 

const results = await Promise.allSettled([
  Promise.resolve('成功1'),
  Promise.reject('失敗'),
  Promise.resolve('成功2')
]);

console.log(results);
// [
//   { status: 'fulfilled', value: '成功1' },
//   { status: 'rejected', reason: '失敗' },
//   { status: 'fulfilled', value: '成功2' }
// ]

Promise.race

最初に完了したPromiseの結果を返します。 

// タイムアウト実装の例
const result = await Promise.race([
  fetch('/api/data'),
  new Promise((_, reject) =>
    setTimeout(() => reject('タイムアウト'), 5000)
  )
]);

使い分け早見表

メソッド 動作 使いどころ
Promise.all 全成功 or 1つ失敗で終了 全部必要な時
Promise.allSettled 全完了まで待つ 失敗も知りたい時
Promise.race 最初の1つで終了 タイムアウト実装

直列が正しい場合もある

⚠️ 注意：何でも並列化すればいいわけではない

依存関係がある場合は直列が正しい選択です。 

// ⭕ 直列が正しい例（依存関係あり）
async function checkout() {
  // 1. まずユーザー情報を取得
  const user = await getUser();

  // 2. ユーザーIDを使って注文を作成（依存！）
  const order = await createOrder(user.id);

  // 3. 注文IDを使って支払い処理（依存！）
  const payment = await processPayment(order.id);

  return payment;
}

// ❌ 間違い：依存関係があるのに並列化
// createOrderにはuser.idが必要なので、
// Promise.allにはできない！
📝 まとめ
  • 依存関係がない → Promise.allで並列化
  • 依存関係がある → 直列（await を連続）
  • 失敗しても続けたい → Promise.allSettled
  • 最速の1つでOK → Promise.race

クイズ：次のコードの問題点は？ 

async function getData() {
  const user = await fetchUser();
  const posts = await fetchPosts();
  const comments = await fetchComments();
  return { user, posts, comments };
}
解説：3つの処理に依存関係がないなら、 直列に待つ必要はありません。Promise.allで並列実行すれば、 3倍速くなる可能性があります。パフォーマンスレビューで必ず指摘すべき点です。

クイズ2：Promise.all と Promise.allSettled の違いは？

解説：Promise.allは1つでも失敗すると即座にrejectされます。 一方、Promise.allSettledは全Promiseが完了するのを待ち、 成功・失敗の両方を含む結果配列を返します。用途に応じて使い分けましょう。

レビューで指摘すべきポイント

🔍 コードレビューの観点
  • Promise.all vs Promise.allSettled の使い分け：1つの失敗で全体を止めたいならall、個別結果が必要ならallSettled
  • 不要な直列実行：依存関係のないawaitが連続していたらPromise.allで並列化を提案
  • コールバック地獄の検出：3段以上のネストされたコールバックはasync/awaitに書き直すべき

Fetch APIとは？

Fetch APIは、
サーバーとHTTP通信するためのAPIです。

📮 たとえ話：郵便局

fetch = 手紙を送って、返事を待つ
ブラウザからサーバーに「リクエスト」を送り、「レスポンス」を受け取ります。

基本的なGETリクエスト

// 最もシンプルな形
const response = await fetch('/api/users');
const users = await response.json();
console.log(users);

fetchの2段階処理

⚠️ 重要：2回awaitが必要
  1. await fetch() → Responseオブジェクトを取得
  2. await response.json() → 本文をJSONに変換
// ❌ よくある間違い
const data = await fetch('/api/users');  // これはResponseオブジェクト
console.log(data.name);  // undefined

// ⭕ 正しい
const response = await fetch('/api/users');
const data = await response.json();  // JSONに変換
console.log(data.name);  // "太郎"

POSTリクエスト

const response = await fetch('/api/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: '太郎',
    email: 'taro@example.com'
  })
});

const result = await response.json();

HTTPメソッド一覧

メソッド 用途 例

レスポンスのチェック

🔴 超重要：fetchはHTTPエラーでスローしない！

fetch()は404や500でもエラーを投げません。
エラーになるのはネットワーク障害の時だけです。 

// ❌ これだけでは不十分！
try {
  const response = await fetch('/api/not-found');
  const data = await response.json();  // 404でもここに来る！
} catch (error) {
  // ネットワークエラーのみキャッチ
  // 404, 500などはキャッチされない！
}

// ⭕ 正しいエラーチェック
const response = await fetch('/api/users');

if (!response.ok) {
  // 400番台、500番台のエラー
  throw new Error(`HTTP error: ${response.status}`);
}

const data = await response.json();
💡 response.okとは

response.okは、ステータスコードが200-299の場合にtrue。
404や500の場合はfalseなので、必ずチェックしましょう。

完全なエラーハンドリング例

async function fetchUsers() {
  try {
    const response = await fetch('/api/users');

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const users = await response.json();
    return users;

  } catch (error) {
    if (error.name === 'TypeError') {
      // ネットワークエラー
      console.error('ネットワークに接続できません');
    } else {
      console.error('エラー:', error.message);
    }
    return [];
  }
}

クイズ：fetch()のレスポンスでJSONを取得するには？

解説：response.json()はPromiseを返すので、 awaitが必要です。response.dataは存在せず、 JSON.parse()はResponseオブジェクトには使えません。
📝 まとめ
  • fetch()はPromiseを返す（2回awaitが必要）
  • HTTPエラー(404,500)ではスローしない → response.okをチェック
  • ネットワークエラーはtry/catchでキャッチ
  • POSTはmethod, headers, bodyを指定

イベントループ全体図

JavaScriptの非同期処理を支えるイベントループを
図で理解しましょう。

🔄 イベントループ図解

実行順序のルール

イベントループは以下の順序で処理を実行します。

  1. Call Stackが空になるまで同期処理を実行
  2. Microtask Queueを全て処理（Promise.then, queueMicrotask等）
  3. Task Queueから1つだけタスクを取り出して実行（setTimeout, setInterval等）
  4. 1に戻る（このサイクルを繰り返す）
⚠️ 超重要：MicrotaskはTaskより先に実行される

Promise.then()のコールバック（Microtask）は、
setTimeout()のコールバック（Task）よりも常に先に実行されます。
たとえsetTimeoutが先に登録されていても同じです。

コード例で確認

console.log('1: 同期処理');

setTimeout(() => {
  console.log('2: setTimeout（Task Queue）');
}, 0);

Promise.resolve().then(() => {
  console.log('3: Promise.then（Microtask Queue）');
});

console.log('4: 同期処理');

// 出力順序:
// 1: 同期処理
// 4: 同期処理
// 3: Promise.then（Microtask Queue）  ← setTimeoutより先！
// 2: setTimeout（Task Queue）

ポイント：setTimeout(0)で0ミリ秒を指定しても、
Promise.thenの方が先に実行されます。
これはMicrotask QueueがTask Queueより優先度が高いからです。

もう少し複雑な例

console.log('A');

setTimeout(() => console.log('B'), 0);

Promise.resolve()
  .then(() => console.log('C'))
  .then(() => console.log('D'));

setTimeout(() => console.log('E'), 0);

console.log('F');

// 出力順序:
// A → F → C → D → B → E
//
// 解説:
// 1. 同期処理: A, F
// 2. Microtask: C, D（Promiseチェーン全部）
// 3. Task: B（最初のsetTimeout）
// 4. Microtask: なし
// 5. Task: E（2番目のsetTimeout）
