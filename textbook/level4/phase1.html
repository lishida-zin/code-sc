Node.jsはブラウザの外でJSを動かす

JavaScriptは元々ブラウザ専用でした。

Node.jsのおかげで、サーバー側でもJSが動きます。

🏠 たとえ話

JavaScript = 料理のレシピ
ブラウザ = 家庭のキッチン
Node.js = プロの厨房

同じレシピ（JS）を、違う場所でも使えるようになりました。

V8エンジンとは

Node.jsはGoogle ChromeのJSエンジンを使っています。

このエンジンの名前がV8です。

✓ V8エンジンの特徴
  • 高速: JIT（Just-In-Time）コンパイル
  • 信頼性: Googleが継続的に改良
  • 最新ES対応: 新しいJS機能をすぐサポート

語源：なぜ「Node」？

「Node」は「結び目・接点」という意味です。

ネットワーク上の接点として機能することから名付けられました。

ノンブロッキングI/Oとは

I/OとはInput/Output（入出力）のことです。

  • ファイルの読み書き
  • データベースへのアクセス
  • ネットワーク通信
ブロッキング（同期）
// 待っている間、何もできない
const data = readFileSync('big.txt');
// ↑ 読み込み完了まで止まる
console.log('次の処理');
// 1秒後にやっと実行

レストランで注文後、料理が来るまで立ち尽くす

ノンブロッキング（非同期）
// 待たずに次へ進む
readFile('big.txt', (data) => {
  // 読み込み完了時に実行
});
console.log('次の処理');
// すぐ実行される

注文後、席で待ちながら他のことができる

Node.jsが得意なこと・苦手なこと

✓ 得意
  • I/O多め: API、リアルタイム通信
  • 同時接続: チャット、通知
  • マイクロサービス: 軽量サーバー
⚠️ 苦手
  • CPU負荷の高い処理: 画像処理、機械学習
  • 重い計算: 大量データの計算

シングルスレッドなので、重い計算中は他の処理がブロックされます。

ESM vs CommonJS

📚 このページで学ぶこと
  • CommonJS（CJS）とは
  • ES Modules（ESM）とは
  • 2026年の推奨はどちらか

モジュールシステムとは

コードをファイルに分割して管理する仕組みです。

Node.jsには2つの方式があります。

CommonJS（CJS）- 古い方式

Node.js誕生時から使われてきた方式です。 

// エクスポート（公開）
// math.js
function add(a, b) {
  return a + b;
}
module.exports = { add };

// インポート（読み込み）
// main.js
const { add } = require('./math');
console.log(add(1, 2)); // 3
⚠️ CommonJSの特徴
  • require()でインポート
  • module.exportsでエクスポート
  • 同期的に読み込み
  • Node.js専用（ブラウザでは動かない）

ES Modules（ESM）- 新しい方式

JavaScriptの標準仕様として策定されました。 

// エクスポート（公開）
// math.js
export function add(a, b) {
  return a + b;
}

// インポート（読み込み）
// main.js
import { add } from './math.js';
console.log(add(1, 2)); // 3
✓ ESMの特徴
  • importでインポート
  • exportでエクスポート
  • 非同期的に読み込み可能
  • ブラウザでもNode.jsでも動く
  • 2026年の標準

比較まとめ

❌ CommonJS（古い）
// インポート
const express = require('express');
const { Router } = require('express');

// エクスポート
module.exports = router;
module.exports = { add, subtract };
⭕ ESM（推奨）
// インポート
import express from 'express';
import { Router } from 'express';

// エクスポート
export default router;
export { add, subtract };

default export vs named export

// named export（名前付き）
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }

// 使う側
import { add, subtract } from './math.js';

// default export（デフォルト）
export default function main() { ... }

// 使う側（名前は自由）
import myMain from './main.js';
import anyName from './main.js';

// ❌ レビューで指摘すべき

// ⭕ こう直すべき

2026年の新規プロジェクトでCJSは非推奨です。

package.jsonとは

プロジェクトの設計図です。

プロジェクト名、依存パッケージ、実行コマンドなどを記録します。

🏠 たとえ話

package.json = 料理の材料リスト＋作り方メモ
誰が見ても同じ環境を再現できます。

基本構造

{
  "name": "my-app",
  "version": "1.0.0",
  "type": "module",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "dev": "node --watch index.js",
    "test": "vitest"
  },
  "dependencies": {
    "express": "^5.0.0"
  },
  "devDependencies": {
    "vitest": "^3.0.0"
  }
}

"type": "module" - 重要！

この設定がESMを有効にします。

❌ 設定なし（または "type": "commonjs"）
// デフォルトはCommonJS
// import文はエラーになる
import express from 'express';
// SyntaxError: Cannot use import
⭕ "type": "module"
// ESMが有効
// import文が使える
import express from 'express';
// OK!
🔍 コードレビューで見抜くべき問題

"type" 未設定

// ❌ package.jsonに"type"がない
{
  "name": "my-app",
  "dependencies": { ... }
}

// ⭕ "type": "module" を追加
{
  "name": "my-app",
  "type": "module",
  "dependencies": { ... }
}

新規プロジェクトでは必ず"type": "module"を設定しましょう。

scripts - コマンドの定義

よく使うコマンドに名前を付けて登録できます。 

"scripts": {
  "start": "node index.js",        // npm start
  "dev": "node --watch index.js",  // npm run dev
  "build": "tsc",                  // npm run build
  "test": "vitest",                // npm test
  "lint": "eslint ."               // npm run lint
}

startとtestはrunなしで実行できます。

dependencies vs devDependencies

dependencies（本番で必要）
"dependencies": {
  "express": "^5.0.0",
  "prisma": "^6.0.0"
}
// npm install express

アプリの実行に必要なパッケージ

devDependencies（開発時のみ）
"devDependencies": {
  "vitest": "^3.0.0",
  "eslint": "^9.0.0"
}
// npm install -D vitest

テストやビルドに必要なパッケージ

バージョン指定の記号

  • "express": "5.0.0" - 完全一致
  • "express": "^5.0.0" - 5.x.x（メジャー固定）
  • "express": "~5.0.0" - 5.0.x（マイナー固定）
  • "express": "*" - 最新（危険！）

イベントループ

📚 このページで学ぶこと

イベントループとは

Node.jsが非同期処理を実現する仕組みです。

🏠 たとえ話

イベントループ = レストランのウェイター

  • 注文を受ける（タスクを受け取る）
  • 厨房に伝える（バックグラウンドで処理）
  • 料理ができたら運ぶ（コールバック実行）
  • 常に複数テーブルを巡回（ループ）

コールスタック

「今実行中の関数」を積み上げるスタックです。 

function first() {
  console.log('1');
  second();
  console.log('3');
}

function second() {
  console.log('2');
}

first();
// 出力: 1, 2, 3

// コールスタックの変化:
// [first] → [first, second] → [first] → []

スタック = 後入れ先出し（LIFO）のデータ構造です。

タスクキュー（マクロタスク）

setTimeoutなどのコールバックが並ぶ列です。 

console.log('1');

setTimeout(() => {
  console.log('2'); // タスクキューに入る
}, 0);

console.log('3');

// 出力: 1, 3, 2
// setTimeoutは0msでも「後回し」になる

マイクロタスク

Promiseの.then()はマイクロタスクキューに入ります。

マイクロタスクはタスクより優先されます。 

console.log('1');

setTimeout(() => {
  console.log('timeout'); // タスクキュー
}, 0);

Promise.resolve().then(() => {
  console.log('promise'); // マイクロタスク
});

console.log('2');

// 出力: 1, 2, promise, timeout
// マイクロタスク → タスク の順で実行

実行順序まとめ

✓ イベントループの優先順位
  1. コールスタック: 同期コードを実行
  2. マイクロタスク: Promise.then, queueMicrotask
  3. タスクキュー: setTimeout, setInterval, I/O

同期的ブロッキング

// ❌ 重い同期処理（イベントループをブロック）
function processData() {
  for (let i = 0; i < 10000000000; i++) {
    // 重い計算...
  }
}
// この間、他のリクエストが処理できない！

// ⭕ 非同期に分割
async function processData() {
  for (let i = 0; i < chunks.length; i++) {
    await processChunk(chunks[i]);
    // 各チャンク処理後、他のタスクが実行できる
  }
}

イベントループをブロックすると全体が止まります。

非同期処理の歴史

Node.jsの非同期処理は3世代あります。

  1. コールバック（古い）
  2. Promise（ES2015）
  3. async/await（ES2017、現在の標準）

コールバック地獄

コールバックをネストすると読みにくくなります。

❌ コールバック地獄
readFile('a.txt', (err, a) => {
  if (err) return handleError(err);
  readFile('b.txt', (err, b) => {
    if (err) return handleError(err);
    readFile('c.txt', (err, c) => {
      if (err) return handleError(err);
      // どんどんネストが深くなる...
    });
  });
});

Promiseで解決

Promiseは非同期処理をチェーンできます。 

readFilePromise('a.txt')
  .then(a => readFilePromise('b.txt'))
  .then(b => readFilePromise('c.txt'))
  .then(c => {
    // すべて完了
  })
  .catch(err => {
    // エラー処理を一箇所にまとめられる
  });

async/awaitでさらに読みやすく

async/awaitは同期コードのように書けます。

⭕ async/await（2026年推奨）
async function readAllFiles() {
  try {
    const a = await readFilePromise('a.txt');
    const b = await readFilePromise('b.txt');
    const c = await readFilePromise('c.txt');
    // すべて完了
  } catch (err) {
    // エラー処理
  }
}

エラーハンドリング

async/awaitではtry-catchを使います。

❌ try-catch漏れ
async function getUser(id) {
  // エラーが起きたら
  // 呼び出し元に伝播する
  const user = await db.findUser(id);
  return user;
}

// 呼び出し側でも未処理なら
// プログラムがクラッシュ！
⭕ 適切なエラー処理
async function getUser(id) {
  try {
    const user = await db.findUser(id);
    return user;
  } catch (err) {
    console.error('DB error:', err);
    throw new Error('User not found');
  }
}

並列実行：Promise.all

複数の非同期処理を並列に実行できます。

❌ 直列実行（遅い）
// 3秒 + 3秒 = 6秒かかる
const user = await fetchUser();
const posts = await fetchPosts();
const comments = await fetchComments();
⭕ 並列実行（速い）
// 最も遅い処理の時間（3秒）で完了
const [user, posts, comments] =
  await Promise.all([
    fetchUser(),
    fetchPosts(),
    fetchComments()
  ]);

Promise.allSettled

一部が失敗しても全結果を取得できます。 

const results = await Promise.allSettled([
  fetchUser(),     // 成功
  fetchPosts(),    // 失敗
  fetchComments()  // 成功
]);

results.forEach(result => {
  if (result.status === 'fulfilled') {
    console.log('成功:', result.value);
  } else {
    console.log('失敗:', result.reason);
  }
});

ファイル操作

fsモジュールとは

Node.jsのファイルシステムモジュールです。

fs = File System の略です。

3つのAPI形式

  • fs - コールバック形式（古い）
  • fs/promises - Promise形式（推奨）
  • fs...Sync - 同期形式（危険）

fs/promises（推奨）

async/awaitで使える形式です。 

import { readFile, writeFile } from 'fs/promises';

// ファイル読み込み
const content = await readFile('data.txt', 'utf8');
console.log(content);

// ファイル書き込み
await writeFile('output.txt', 'Hello, World!');

// JSONファイル読み込み
const json = JSON.parse(
  await readFile('config.json', 'utf8')
);

同期APIの危険性

❌ 同期API（ブロッキング）
import { readFileSync } from 'fs';

// この間、他の処理が止まる！
const data = readFileSync('big-file.txt');
// 全リクエストが待たされる

サーバーで使うと全体がフリーズ

⭕ 非同期API
import { readFile } from 'fs/promises';

// 他の処理をブロックしない
const data = await readFile('big-file.txt');
// 待っている間も他のリクエストを処理

サーバーが応答し続けられる

🔍 コードレビューで見抜くべき問題

同期API使用

// ❌ 同期API（Sync）を見つけたら指摘
const data = fs.readFileSync('file.txt');
const exists = fs.existsSync('file.txt');
fs.writeFileSync('file.txt', data);

// ⭕ 非同期APIを使う
const data = await fs.promises.readFile('file.txt');
// または
import { readFile } from 'fs/promises';
const data = await readFile('file.txt');

例外：CLIツールの初期化など、起動時の1回のみなら許容。
サーバーのリクエスト処理中は絶対NG。

よく使うfs操作

import {
  readFile, writeFile,
  readdir, mkdir, rm,
  stat, access
} from 'fs/promises';

// ディレクトリ一覧
const files = await readdir('./data');

// ディレクトリ作成
await mkdir('./output', { recursive: true });

// ファイル削除
await rm('./temp.txt');

// ファイル情報取得
const info = await stat('./data.txt');
console.log(info.size, info.mtime);

// ファイル存在確認
try {
  await access('./config.json');
  console.log('存在する');
} catch {
  console.log('存在しない');
}

ストリーム

大きなファイルを少しずつ処理する仕組みです。

🏠 たとえ話

バケツで一気に水を運ぶ（メモリに全部読み込み）
vs
ホースで少しずつ流す（ストリーム）

大量の水（データ）はホースが効率的。 

import { createReadStream, createWriteStream } from 'fs';

// 大きなファイルを少しずつ読む
const readStream = createReadStream('huge-file.txt');
const writeStream = createWriteStream('output.txt');

// パイプで繋ぐ（コピー）
readStream.pipe(writeStream);

// イベントで処理
readStream.on('data', (chunk) => {
  console.log('読み込み中:', chunk.length, 'bytes');
});

readStream.on('end', () => {
  console.log('完了');
});

環境変数とは

プログラムの外部から設定値を渡す仕組みです。

🏠 たとえ話

環境変数 = レシピの調味料の量
同じレシピでも、環境（家庭/レストラン）で量を変える。
コードを変えずに設定だけ変更できる。

process.env

Node.jsではprocess.envでアクセスします。 

// 環境変数を読み取る
const port = process.env.PORT || 3000;
const dbUrl = process.env.DATABASE_URL;
const apiKey = process.env.API_KEY;

// 使用例
app.listen(port, () => {
  console.log(`Server running on port ${port}`);
});

なぜ環境変数を使う？

✓ メリット
  • 機密情報を隠す: コードに直接書かない
  • 環境ごとに変更: 開発/本番で値を変える
  • 設定の一元管理: 変更が簡単

dotenv

.envファイルから環境変数を読み込むライブラリです。 

// .env ファイル
PORT=3000
DATABASE_URL=postgres://localhost/mydb

// 起動時にチェック
const required = ['DATABASE_URL', 'JWT_SECRET'];

for (const key of required) {
  if (!process.env[key]) {
    console.error(`Missing required env: ${key}`);
    process.exit(1);
  }
}

  • コードの違い

2026年の主要フレームワーク

Node.jsには多くのWebフレームワークがあります。

代表的な4つを比較します。

Express - 王道・安定

📦 Express
  • 特徴: 最も人気、巨大エコシステム
  • 強み: 情報が多い、学習しやすい
  • 弱み: 古い設計、TypeScript対応が後付け
  • 推奨: 学習用、レガシー保守
import express from 'express';
const app = express();

app.get('/users/:id', (req, res) => {
  res.json({ id: req.params.id });
});

app.listen(3000);

Fastify - 高性能

🚀 Fastify
  • 特徴: Express互換で高速
  • 強み: JSON最適化、スキーマ検証内蔵
  • 弱み: Expressより情報が少ない
  • 推奨: 本番API、パフォーマンス重視
import Fastify from 'fastify';
const fastify = Fastify();

fastify.get('/users/:id', async (request) => {
  return { id: request.params.id };
});

await fastify.listen({ port: 3000 });

Hono - 超軽量・Edge対応

🔥 Hono
  • 特徴: 超軽量（〜14KB）、マルチランタイム
  • 強み: Edge対応、TypeScript設計
  • 弱み: 新しい、エコシステムが小さい
  • 推奨: Cloudflare Workers、Serverless
import { Hono } from 'hono';
const app = new Hono();

app.get('/users/:id', (c) => {
  return c.json({ id: c.req.param('id') });
});

export default app;

NestJS - エンタープライズ

🏢 NestJS
  • 特徴: Angular風の構造化、DI内蔵
  • 強み: 大規模開発、TypeScript完全対応
  • 弱み: 学習曲線が高い、オーバーヘッド
  • 推奨: 大規模TypeScript、チーム開発
import { Controller, Get, Param } from '@nestjs/common';

@Controller('users')
export class UsersController {
  @Get(':id')
  findOne(@Param('id') id: string) {
    return { id };
  }
}
