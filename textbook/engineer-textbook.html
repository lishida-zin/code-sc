HTMLって何だろう？

HTMLは「HyperText Markup Language」の略です。

難しく聞こえますが、簡単に言うと：

💡 かんたんな説明

HTMLは「Webページの骨組み」を作る言語です。

たとえ話：家を建てること

Webページを「家」に例えてみましょう。

HTMLは骨組み、CSSは見た目

役割 家で言うと Webで言うと
HTML 骨組み・柱・壁の位置 文字・画像・ボタンの配置
CSS 壁紙・家具・色 色・大きさ・フォント
JavaScript 電気・水道・動くもの クリック・アニメーション

なぜHTMLが必要なの？

ブラウザ（ChromeやSafari）は、HTMLを読んで画面を表示します。

HTMLがないと、ブラウザは「何を表示すればいいか」わかりません。

❌ HTMLなし

ただの文字の羅列

これは見出しこれは本文これはリンク

⭕ HTMLあり

これは見出し

これは本文

これはリンク

HTMLの正体：「タグ」で囲む

HTMLでは、「タグ」という印で文字を囲みます。 

<h1>これは見出し</h1>
<p>これは本文</p>
<a href="...">これはリンク</a>

タグがあることで、ブラウザは「これは見出しだな」「これはリンクだな」と理解します。

🔤 用語の意味
  • h1 = heading 1（見出し1）
  • p = paragraph（段落）
  • a = anchor（リンクのこと）

まとめ

✨ 覚えておこう
  1. HTMLはWebページの骨組みを作る言語
  2. タグで文字を囲んで、意味を伝える
  3. HTMLが構造、CSSが見た目、JavaScriptが動き

2. タグの基本

📚 このページで学ぶこと
  • タグの形（開始タグ・終了タグ）
  • 属性ってなに？
  • よくある間違いと直し方

タグの基本形

HTMLのタグは、「箱」のようなものです。

箱を開けて、中身を入れて、閉じる。

タグは「開始」「内容」「終了」の3つでできている

<p>これは段落です</p>

↑開始タグ  ↑内容   ↑終了タグ
💡 ポイント

終了タグにはスラッシュ（/）がついています。

<p> → </p>

属性：追加の情報を与える

属性は、タグに「追加の説明」を与えます。

たとえば「どこにリンクするか」「画像のファイル名は何か」など。 

<a href="https://google.com">Googleへ</a>

   ↑属性名  ↑属性値
🔤 属性のルール
  • 属性は開始タグの中に書く
  • 属性名は小文字で書く
  • 属性値はダブルクォート（"）で囲む

空要素：閉じタグがいらないタグ

一部のタグは、中身を持たないので終了タグが不要です。

タグ 意味 使い方
<br> 改行 ここで改行<br>次の行
<hr> 水平線 区切りを入れる
<img> 画像 <img src="photo.jpg">
<input> 入力欄 フォームの入力欄

よくある間違い

❌ 間違い

終了タグ忘れ

<p>段落1
<p>段落2
⭕ 正しい

ちゃんと閉じる

<p>段落1</p>
<p>段落2</p>
❌ 間違い

入れ子が崩れている

<p><strong>太字</p></strong>
⭕ 正しい

開いた順の逆で閉じる

<p><strong>太字</strong></p>
📝 覚え方

「先に開けたら、後に閉じる」

お弁当箱と同じ。大きい箱の中に小さい箱を入れたら、小さい箱から先に閉じる。

まとめ

✨ 覚えておこう
  1. タグは開始タグ・内容・終了タグの3つでできている
  2. 属性で追加の情報を与える（href、srcなど）
  3. 入れ子は「開いた順の逆で閉じる」
❓ 確認クイズ

3. 文書構造

📚 このページで学ぶこと
  • HTMLファイルの基本形
  • head と body の違い
  • 必ず書くもの

HTMLファイルの全体像

すべてのHTMLファイルは、同じ「形」を持っています。

HTMLファイルの構造

<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>ページタイトル</title>
</head>
<body>
  ここに表示する内容
</body>
</html>

各部分の役割

DOCTYPE宣言

<!DOCTYPE html> は「これはHTML5です」という宣言。

必ず1行目に書く。これがないと、古いモードで表示される。

head：見えない情報

<head>の中には、ユーザーに見えない設定を書きます。

タグ 役割
<meta charset="UTF-8"> 日本語を正しく表示する
<title> ブラウザのタブに表示
<link> CSSファイルを読み込む

body：見える内容

<body>の中には、ユーザーに見える内容を書きます。

文字、画像、ボタン、リンク...全部ここに入れます。

⚠️ よくある間違い
  • <title>をbodyに書く → タブに表示されない
  • charsetを書き忘れる → 文字化けする

まとめ

✨ 覚えておこう
  1. DOCTYPEは1行目に必ず書く
  2. headは見えない設定（title、charsetなど）
  3. bodyは見える内容（文字、画像など）

見出しの大きさと重要度

aはanchor（アンカー＝錨）の略。

<a href="https://google.com">Googleへ</a>
属性 意味 例

target 開き方 "_blank"（新しいタブ）

画像：imgタグ

imgはimage（画像）の略。

終了タグは不要です（空要素）。 

<img src="photo.jpg" alt="写真の説明">
属性 意味 必須？
src 画像ファイルの場所 必須
alt 画像の説明文 必須
width 横幅 任意

alt属性がなぜ重要？

🔴 alt属性がないと...

altがない！

⭕ 良い例 
<img src="cat.jpg" alt="ソファで眠る茶色の猫">

内容がわかる説明

まとめ

✨ 覚えておこう
  1. リンクは<a href="...">で作る
  2. 画像は<img src="..." alt="...">で表示
  3. alt属性は必須（アクセシビリティのため）

2種類のリスト

タグ 名前 使う場面 見た目
<ul> Unordered List（順序なし） 順番が関係ない項目 ・で表示

書き方

📋 順序なしリスト 
<ul>
  <li>りんご</li>
  <li>みかん</li>
  <li>バナナ</li>
</ul>

結果：

  • りんご
  • みかん
  • バナナ
🔢 順序ありリスト 
<ol>
  <li>材料を準備</li>
  <li>混ぜる</li>
  <li>焼く</li>
</ol>

結果：

  1. 材料を準備
  2. 混ぜる
  3. 焼く

liタグだけ書いてul/olを書き忘れる

⭕ <ul><li>項目1</li><li>項目2</li></ul>

まとめ

✨ 覚えておこう
  1. ulは順序なし（・で表示）
  2. olは順序あり（1.2.3.で表示）
  3. 項目はliタグで書く
  4. ul/olの中にliを入れる（liだけはNG）

セマンティックって何？

セマンティックは「意味のある」という意味です。

タグを見ただけで「ここは何の役割か」がわかるようにします。

divだらけ vs セマンティックタグ

主なセマンティックタグ

タグ 意味 使う場所
<header> ヘッダー（頭） ページ上部、ロゴやタイトル
<nav> ナビゲーション メニュー、リンク集

<footer> フッター（足） ページ下部、著作権情報

なぜセマンティックが大事？

CSSってなに？

CSSは「Cascading Style Sheets」の略です。

HTMLが「骨組み」なら、CSSは「見た目」を決めます。

💡 かんたんな説明

CSSは「色・大きさ・配置」を決める言語です。

HTMLとCSSの関係

CSSで何ができる？

できること 例
色を変える 文字を赤に、背景を青に
大きさを変える 文字を大きく、画像を小さく
配置を変える 中央揃え、横並び
余白を調整 要素の間隔を広げる

CSSの書き方

セレクタ {
  プロパティ: 値;
}

例：
p {
  color: red;
  font-size: 20px;
}
部分 意味 例
セレクタ どの要素に適用するか p（段落に）
プロパティ 何を変えるか color（色を）
値 どう変えるか red（赤に）

まとめ

✨ 覚えておこう
  1. CSSは見た目を決める言語
  2. HTML（構造）＋ CSS（見た目）＝ Webページ
  3. 「セレクタ { プロパティ: 値; }」の形で書く

セレクタ＝「どの要素に適用するか」

セレクタは、CSSをどの要素に適用するかを指定します。

3つの基本セレクタ

種類 書き方 意味
要素セレクタ p { } すべての<p>タグ
クラスセレクタ .box { } class="box"の要素
IDセレクタ #header { } id="header"の要素

要素セレクタ

p {
  color: blue;
}
/* すべての段落が青くなる */

クラスセレクタ（.ドット）

.highlight {
  background: yellow;
}

/* HTML側 */
<p class="highlight">黄色背景</p>

IDセレクタ（#シャープ）

#main-title {
  font-size: 32px;
}

/* HTML側 */
<h1 id="main-title">タイトル</h1>
⚠️ クラスとIDの違い
class id
同じページで 何度でも使える 1回だけ
用途 共通のスタイル 唯一の要素
優先度 低い 高い

詳細度（優先順位）

同じ要素に複数のスタイルがあると、詳細度が高い方が勝ちます。

🏆 優先順位（高い順）
  1. !important（最強、でも使わない方がいい）
  2. IDセレクタ（#header）
  3. クラスセレクタ（.box）
  4. 要素セレクタ（p, div）

まとめ

✨ 覚えておこう
  1. 要素セレクタ：p（タグ名そのまま）
  2. クラスセレクタ：.名前（ドット＋名前）
  3. IDセレクタ：#名前（シャープ＋名前）
  4. 優先度：ID ＞ クラス ＞ 要素

Flexboxってなに？

Flexboxは、要素を簡単に並べるための仕組みです。

「横並び」「中央揃え」がとても簡単にできます。

基本の使い方

.container {

}

display: flex で横並びに

よく使うプロパティ

プロパティ 意味 値の例

align-items 縦方向の揃え center, flex-start

14. Grid

📚 このページで学ぶこと
  • CSS Gridとは
  • Flexboxとの違い
  • グリッドレイアウトの作り方

Gridってなに？

Gridは、格子状（グリッド）に要素を並べる仕組みです。

Flexboxは「一列」、Gridは「複数行×複数列」が得意です。

Flexboxは一列、Gridは格子状

基本の使い方

.container {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;  /* 3列 */
  gap: 20px;                            /* 隙間 */
}
プロパティ 意味 値の例
grid-template-columns 列の幅 1fr 1fr 1fr（3等分）
grid-template-rows 行の高さ 100px auto
gap 隙間 20px
💡 frって何？

frは「fraction（分数）」の略。

1fr 1fr 1frなら「1:1:1で3等分」という意味です。

FlexboxとGridの使い分け

Flexbox Grid
得意なこと 一列に並べる 格子状に並べる
使う場面 ナビ、ボタン並び カード一覧、全体レイアウト

まとめ

✨ 覚えておこう
  1. display: gridで格子状レイアウト
  2. grid-template-columnsで列数を決める
  3. 一列ならFlexbox、格子状ならGrid

変数と定数

📚 このページで学ぶこと

  • let、const、varの違い
  • なぜvarを使わないのか（2026年のベストプラクティス）

変数 = データを入れる「箱」

プログラミングでは、データを一時的に保存しておく必要があります。

その「保存場所」が変数です。

📦 イメージ

変数は「ラベル付きの箱」と考えてください。

  • 箱に名前（ラベル）をつける → userName
  • 箱の中にデータを入れる → "太郎"
  • 後で箱の中身を取り出せる → userNameで"太郎"を参照

3つの宣言方法

JavaScriptで変数を作る方法は3つあります。 

// 1. const: 再代入できない（定数）
const TAX_RATE = 0.1;

// 2. let: 再代入できる（変数）
let count = 0;
count = 1;  // OK

// 3. var: 古い書き方（使わない）
var oldStyle = "避けるべき";

const と let の使い分け

⭕ const（基本はこれ） 
// 変わらない値
const PI = 3.14159;
const userName = "太郎";
const config = { debug: true };

一度入れたら変えないものに使う

🔄 let（必要な時だけ） 
// 変わる値
let count = 0;
count++;  // 1になる

let total = 0;
total = total + 100;

後から値を変えるものに使う

💡 ベストプラクティス

まず const で書く。
再代入が必要になったら let に変える。
この順番で考えると、バグが減ります。

なぜ var を使わないのか

varには危険な特徴があります。

⚠️ varの問題点

問題1: 同じ名前で再宣言できてしまう

var name = "太郎";
var name = "次郎";  // エラーにならない（上書きされる）

// let/const なら
let name = "太郎";
let name = "次郎";  // エラー！（気づける）

問題2: スコープが広すぎる（関数スコープ）

if (true) {
  var leaked = "漏れる";  // ブロックの外でも使える
  let safe = "安全";      // ブロックの中だけ
}
console.log(leaked);  // "漏れる"（意図しない動作）
console.log(safe);    // エラー（正しい動作）

2015年にlet/constが導入されてから、varを使う理由はなくなりました。

🔍 レビューで指摘すべきポイント

AIが書いたコードにvarがあったら、
「let または const を使うべき」と指摘しましょう。

命名規則

⭕ 良い命名

// 定数は大文字+アンダースコア

ラクダ（camel）のコブのように見えることから名付けられました。

データ型

📚 このページで学ぶこと

  • 参照型とは

データには「型」がある

JavaScriptで扱うデータには、それぞれ「型」があります。

型を理解することで、バグの原因が見えるようになります。

プリミティブ型（基本型）

最も基本的なデータの種類です。

型 説明 例
string 文字列 "こんにちは", 'Hello'
number 数値（整数・小数） 42, 3.14
boolean 真偽値 true, false
undefined 未定義 undefined
null 空（意図的に空） null
bigint 巨大整数 9007199254740991n
symbol 一意な識別子 Symbol("id")

参照型（オブジェクト型）

複数のデータをまとめて扱う型です。 

// オブジェクト
const user = {
  name: "太郎",
  age: 25
};

// 配列
const numbers = [1, 2, 3, 4, 5];

// 関数
const greet = function() {
  return "こんにちは";
};
⚠️ プリミティブ型と参照型の違い

プリミティブ型: 値そのものがコピーされる

let a = 10;
let b = a;  // 10がコピーされる
b = 20;
console.log(a);  // 10（変わらない）

参照型: 参照（住所）がコピーされる

const obj1 = { name: "太郎" };
const obj2 = obj1;  // 参照がコピーされる
obj2.name = "次郎";
console.log(obj1.name);  // "次郎"（変わってしまう！）

typeof で型を確認

typeof演算子を使うと、データの型を確認できます。 

typeof "hello"     // "string"
typeof 42          // "number"
typeof true        // "boolean"
typeof undefined   // "undefined"

比較演算子（最重要！）

🔥 == と === の違い

これは最もバグを生みやすいポイントです。

❌ ==（等価演算子） 
// 型変換してから比較（危険）

型が違っても true になる

0 === false  // false
null === undefined  // false
"" === 0     // false

型が違えば false になる

💡 ベストプラクティス

常に === を使う。
== を使う理由がある場面は、ほぼありません。
AIが書いたコードに == があったら、即座に指摘しましょう。

その他の比較演算子

5 > 3    // true（より大きい）

5 <= 4   // false（以下）
5 !== 3  // true（厳密不等価）

関数 = 処理をまとめたもの

同じ処理を何度も書くのは面倒ですし、ミスの元です。

関数を使えば、処理を一箇所にまとめて再利用できます。

🏭 イメージ

関数は「工場」のようなものです。
材料（引数）を入れると、製品（戻り値）が出てきます。

関数の3つの書き方

1. 関数宣言

// 伝統的な書き方
function greet(name) {
  return `こんにちは、${name}さん`;
}

greet("太郎");  // "こんにちは、太郎さん"

2. 関数式

// 変数に関数を代入
const greet = function(name) {
  return `こんにちは、${name}さん`;
};

greet("太郎");  // "こんにちは、太郎さん"

3. アロー関数（現代的）

// ES6から追加された書き方
const greet = (name) => {
  return `こんにちは、${name}さん`;
};

// 1行で書ける場合は省略できる
const greet = (name) => `こんにちは、${name}さん`;

// 引数が1つなら括弧も省略可
const greet = name => `こんにちは、${name}さん`;
💡 2026年のベストプラクティス

アロー関数を基本に使う。
ただし、thisの挙動が異なるため、
オブジェクトのメソッドでは関数宣言を使う場面もあります。

引数とデフォルト値

// デフォルト値を設定できる
const greet = (name = "ゲスト") => {
  return `こんにちは、${name}さん`;
};

greet();        // "こんにちは、ゲストさん"
greet("太郎");  // "こんにちは、太郎さん"

戻り値

// return で値を返す
const add = (a, b) => {
  return a + b;
};

const result = add(3, 5);  // 8

// return がないと undefined
const noReturn = () => {
  console.log("処理だけ");
};
const result2 = noReturn();  // undefined

関数宣言 vs 関数式の違い

⚠️ ホイスティング（巻き上げ）

関数宣言は、宣言前に呼び出せる（ホイスティング）

greet();  // OK: "こんにちは"

function greet() {
  return "こんにちは";
}

関数式・アロー関数は、宣言前に呼び出せない

greet();  // エラー！

const greet = () => "こんにちは";

スコープ = 変数が見える範囲

変数には「見える範囲」があります。これをスコープと呼びます。

🏠 イメージ

スコープは「部屋」のようなものです。
部屋の中で宣言した変数は、その部屋の中でしか使えません。
ただし、外の部屋の変数は中から見えます。

3種類のスコープ

1. グローバルスコープ

// どこからでもアクセスできる
const globalVar = "グローバル";

function test() {
  console.log(globalVar);  // OK: "グローバル"
}

console.log(globalVar);    // OK: "グローバル"

2. 関数スコープ

function test() {
  const localVar = "関数内";
  console.log(localVar);  // OK: "関数内"
}

test();
console.log(localVar);  // エラー！関数の外からは見えない

3. ブロックスコープ（let/const）

if (true) {
  const blockVar = "ブロック内";
  console.log(blockVar);  // OK: "ブロック内"
}

console.log(blockVar);  // エラー！ブロックの外からは見えない

var の問題（復習）

⚠️ varはブロックスコープを無視する 
if (true) {
  var leaked = "漏れる";
  let safe = "安全";
}

console.log(leaked);  // "漏れる"（ブロックの外に漏れる）
console.log(safe);    // エラー（正しくブロック内に留まる）

これがvarを使わない理由の一つです。

スコープチェーン

内側のスコープから外側のスコープの変数にアクセスできます。 

const outer = "外";

function test() {
  const middle = "中";

  function inner() {
    const innerVar = "内";
    console.log(innerVar);  // "内"
    console.log(middle);    // "中"（外側の関数の変数）
    console.log(outer);     // "外"（グローバル変数）
  }

  inner();
}

test();

  • 内から外は見える
  • 外から内は見えない

// 末尾から削除
arr.pop();         // [1, 2, 3]

// 先頭に追加

// 先頭から削除
arr.shift();       // [1, 2, 3]

重要なメソッド: map

配列の各要素を変換して新しい配列を作る。 

const numbers = [1, 2, 3, 4, 5];

// 各要素を2倍にする
const doubled = numbers.map(n => n * 2);
// [2, 4, 6, 8, 10]

// 元の配列は変わらない（非破壊的）
console.log(numbers);  // [1, 2, 3, 4, 5]

重要なメソッド: filter

条件に合う要素だけを抽出して新しい配列を作る。 

const numbers = [1, 2, 3, 4, 5];

// 偶数だけ抽出
const evens = numbers.filter(n => n % 2 === 0);
// [2, 4]

重要なメソッド: reduce

配列を1つの値にまとめる。 

const numbers = [1, 2, 3, 4, 5];

// 合計を求める
const sum = numbers.reduce((acc, n) => acc + n, 0);
// 15

// acc: 累積値（初期値は0）
// n: 現在の要素

メソッドチェーン

メソッドを繋げて書くことができます。 

const users = [
  { name: "太郎", age: 25 },
  { name: "花子", age: 17 },
  { name: "次郎", age: 30 }
];

// 20歳以上のユーザー名だけを取得
const adultNames = users
  .filter(user => user.age >= 20)
  .map(user => user.name);
// ["太郎", "次郎"]
💡 読むコツ

メソッドチェーンは上から順番に読みます。
1. filter で絞り込む → 2. map で変換する
この流れをイメージしましょう。

要素の検索

// 要素が含まれているか

const user = {
  name: "太郎",

// "age" 25

// Object.entries + for...of（推奨）
for (const [key, value] of Object.entries(user)) {
  console.log(key, value);
}

  • メモリ効率: リスナーが1つで済む

  • コード簡潔化: 管理が楽になる

16. 同期と非同期

🎯 このレッスンで読めるようになること
  • 同期処理と非同期処理の違いがわかる
  • なぜ非同期処理が必要なのか説明できる
  • ブロッキングとノンブロッキングを理解できる

同期処理とは？

同期処理（Synchronous）とは、
「上から順番に、1つずつ実行する」処理方式です。

🍳 たとえ話：料理で考える

同期処理 = 1品ずつ作る

  1. ご飯を炊く（10分待つ）
  2. 炊き終わったら味噌汁を作る（5分待つ）
  3. 作り終わったら焼き魚を焼く（7分待つ）

合計：22分かかる 

// 同期処理のコード例
console.log('1番目');
console.log('2番目');
console.log('3番目');

// 出力:
// 1番目
// 2番目
// 3番目

同期処理では、前の行が完了するまで次の行に進みません。

非同期処理とは？

非同期処理（Asynchronous）とは、
「待っている間に、別の処理を進める」方式です。

🍳 たとえ話：効率的な料理

非同期処理 = 同時進行で作る

  1. ご飯を炊飯器にセット（待たない！）
  2. その間に味噌汁を作り始める
  3. 味噌汁を煮込む間に魚を焼き始める

合計：10分程度で完成！ 

// 非同期処理のコード例
console.log('1番目');

setTimeout(() => {
  console.log('2番目（1秒後）');
}, 1000);

console.log('3番目');

// 出力:
// 1番目
// 3番目      ← 先に出る！
// 2番目（1秒後）  ← 後から出る

なぜ非同期処理が必要？

ブラウザはシングルスレッド（1つの処理しかできない）です。
もし同期処理だけだと...

⚠️ 同期処理だけの問題点
  • サーバーからデータ取得中 → 画面がフリーズ
  • 大きなファイル読み込み中 → 操作不能
  • ユーザー体験が最悪になる

ブロッキングとノンブロッキング

用語 意味 例
ブロッキング 処理が終わるまで止まる 同期処理
ノンブロッキング 待たずに次に進む 非同期処理

JavaScriptの非同期処理の例

処理 用途
setTimeout 指定時間後に実行
fetch サーバーからデータ取得
addEventListener ユーザー操作を待つ
ファイル読み込み ファイルを読む

イベントループ（超重要）

JavaScriptが非同期処理を実現する仕組みがイベントループです。

🔄 イベントループの動き（簡略版）
  1. コールスタックで同期処理を実行
  2. 非同期処理はタスクキューに登録される
  3. コールスタックが空になったらキューから取り出して実行
console.log('1');        // → コールスタックで即実行

setTimeout(() => {
  console.log('2');      // → タスクキューに登録
}, 0);

console.log('3');        // → コールスタックで即実行

// 結果: 1 → 3 → 2
// 理由: 同期処理(1,3)が全部終わってからキュー(2)を実行
💡 覚えておくこと

「同期処理が全部終わってから、非同期処理が実行される」
これがJavaScript非同期処理の基本原則です。

クイズ：次のコードの出力順は？ 

console.log('A');
setTimeout(() => console.log('B'), 0);
console.log('C');
解説：setTimeoutは0ミリ秒でも非同期です。 JavaScriptは「同期処理をすべて終えてから非同期処理を実行」します。 だからA→C（同期）が先に出て、B（非同期）が最後になります。
📝 まとめ
  • 同期 = 上から順番に、1つずつ実行
  • 非同期 = 待っている間に別の処理を進める
  • イベントループが「同期→非同期」の順序を管理
  • UIをブロックしないために非同期処理は必須

コールバック（Callback）とは、
「あとで呼び出してもらう関数」のことです。

「処理が終わったら、この関数を呼んでね」と

}

// 使い方
doSomething(() => {
  console.log('終わったよ！');
});

// 出力:
// 処理中...
// 終わったよ！

非同期処理とコールバック

非同期処理では、「終わったら何をするか」を
コールバックで指定します。 

// setTimeout のコールバック
setTimeout(() => {
  console.log('1秒経ちました');
}, 1000);

// addEventListener のコールバック
button.addEventListener('click', () => {
  console.log('クリックされました');
});

コールバック地獄（Callback Hell）

非同期処理を連続で行うと、
コールバックが入れ子になって読みにくくなります。 

// ❌ コールバック地獄（読みにくい！）
getUser(userId, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetails(orders[0].id, (details) => {
      getPaymentInfo(details.paymentId, (payment) => {
        console.log(payment);
        // さらに深くなる...
      });
    });
  });
});
⚠️ コールバック地獄の問題点
  • 読みにくい - インデントが深くなる
  • 保守しにくい - 変更が困難
  • エラー処理が複雑 - 各階層で処理が必要

エラー処理の問題

// 各コールバックでエラー処理が必要
getUser(userId, (error, user) => {
  if (error) {
    console.error('ユーザー取得失敗');
    return;
  }
  getOrders(user.id, (error, orders) => {
    if (error) {
      console.error('注文取得失敗');
      return;
    }
    // さらに続く...
  });
});

この問題を解決するために、
Promiseが生まれました。

クイズ：コールバック地獄の最大の問題点は？

解説：コールバック地獄は実行速度やメモリには影響しません。 問題は「人間が読みにくい」こと。深いインデント、エラー処理の分散、 流れの追いにくさが保守を困難にします。
📝 まとめ
  • コールバック = 「あとで呼んでね」と渡す関数
  • 非同期処理の結果を受け取る古い方法
  • ネストが深くなるとコールバック地獄
  • この問題を解決するためにPromiseが生まれた

18. Promise基礎

🎯 このレッスンで読めるようになること
  • Promiseとは何かを説明できる
  • then/catch/finallyの役割がわかる
  • Promiseの3つの状態を理解できる

Promiseとは？

Promise（プロミス）とは、
「非同期処理の結果を約束するオブジェクト」です。

📝 語源：Promise = 約束

「今は結果がないけど、あとで必ず結果を返すよ」
という約束を表すオブジェクトです。

Promiseの3つの状態

状態 意味 日本語
pending 処理中（まだ結果がない） 保留中
fulfilled 成功（結果が得られた） 成功
rejected 失敗（エラーが発生） 拒否
📦 たとえ話：通販の荷物追跡
  • pending = 配送中
  • fulfilled = 届いた！
  • rejected = 配送失敗...

Promiseの基本構文

// Promiseを作る
const promise = new Promise((resolve, reject) => {
  // 非同期処理
  const success = true;

  if (success) {
    resolve('成功しました');  // 成功時
  } else {
    reject('失敗しました');   // 失敗時
  }
});

// Promiseを使う
promise
  .then(result => {
    console.log(result);  // '成功しました'
  })
  .catch(error => {
    console.log(error);   // '失敗しました'
  });

then / catch / finally

メソッド 呼ばれるタイミング 用途
.then() 成功時（fulfilled） 結果を受け取る
.catch() 失敗時（rejected） エラーを処理
.finally() 成功でも失敗でも 後片付け 
fetch('/api/user')
  .then(response => {
    console.log('成功:', response);
  })
  .catch(error => {
    console.log('失敗:', error);
  })
  .finally(() => {
    console.log('ローディング終了');
  });

すぐにPromiseを作るショートカット

テストやシンプルな処理では、すぐに解決/拒否するPromiseが便利です。 

// すぐに成功するPromise
const success = Promise.resolve('成功！');
success.then(msg => console.log(msg));  // '成功！'

// すぐに失敗するPromise
const fail = Promise.reject('失敗...');
fail.catch(err => console.log(err));  // '失敗...'

// new Promiseを使わなくてOK
// これと同じ:
// new Promise(resolve => resolve('成功！'))

コールバック地獄との比較

// ❌ コールバック地獄
getUser(id, (user) => {
  getOrders(user.id, (orders) => {
    getDetails(orders[0].id, (details) => {
      console.log(details);
    });
  });
});

// ⭕ Promiseで書き直し
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getDetails(orders[0].id))
  .then(details => console.log(details))
  .catch(error => console.error(error));
📝 まとめ
  • Promiseは「あとで結果を返す約束」
  • 状態は pending → fulfilled or rejected
  • .then()で成功、.catch()で失敗を処理
  • .finally()は成功でも失敗でも実行

クイズ：Promiseの状態として存在しないのは？

解説：Promiseの状態はpending/fulfilled/rejectedの3つだけ。 「cancelled」は存在しません。実は標準のPromiseはキャンセルできません。 これはPromiseの設計上の制限として知られています。

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
.catch() がない 「エラーハンドリングを追加すべき」
Promiseを返さない 「return がないとチェーンが切れる」

19. Promiseチェーン

🎯 このレッスンで読めるようになること
  • Promiseチェーンの流れを追える
  • thenの戻り値がどう伝わるか理解できる
  • エラーがどこでキャッチされるか把握できる

Promiseチェーンとは？

.then()は新しいPromiseを返すので、
連続して繋げることができます。これがチェーンです。 

// 基本のチェーン
Promise.resolve(1)
  .then(x => x + 1)   // 2
  .then(x => x * 2)   // 4
  .then(x => console.log(x));  // 4

チェーンの流れを追う

🔗 チェーンのルール
  1. 前の.then()の戻り値が次の引数になる
  2. Promiseを返すと、それが解決されてから次に進む
  3. エラーが起きると.catch()までスキップ
// 実践的な例
fetch('/api/user')
  .then(response => response.json())   // JSONに変換
  .then(user => fetch(`/api/orders/${user.id}`))  // 次のリクエスト
  .then(response => response.json())
  .then(orders => console.log(orders))
  .catch(error => console.error(error));

よくある間違い：returnを忘れる

// ❌ return がない → undefined が渡る
fetch('/api/user')
  .then(response => {
    response.json();  // return がない！
  })
  .then(data => {
    console.log(data);  // undefined
  });

// ⭕ 正しい
fetch('/api/user')
  .then(response => {
    return response.json();  // return が必要
  })
  .then(data => {
    console.log(data);  // 正しいデータ
  });

// ⭕ アロー関数なら省略可
fetch('/api/user')
  .then(response => response.json())  // 暗黙のreturn
  .then(data => console.log(data));

エラーの伝播

// エラーは.catch()まで伝播する
Promise.resolve()
  .then(() => {
    throw new Error('エラー発生！');
  })
  .then(() => {
    console.log('ここは実行されない');
  })
  .then(() => {
    console.log('ここも実行されない');
  })
  .catch(error => {
    console.log('キャッチ:', error.message);
  });
💡 ポイント

エラーが発生すると、途中の.then()はすべてスキップされ、
最初の.catch()に到達します。

クイズ：次のコードの出力は？ 

Promise.resolve(10)
  .then(x => x * 2)
  .then(x => { x + 5; })  // ここに注目
  .then(x => console.log(x));
解説：{ x + 5; }は波括弧があるので、 returnがないと戻り値はundefinedになります。 x => x + 5（括弧なし）なら25ですが、 x => { x + 5; }（波括弧あり）は明示的なreturnが必要です。
📝 まとめ
  • .then()は新しいPromiseを返す → チェーン可能
  • 前の.then()の戻り値が次の引数になる
  • returnを忘れるとundefinedが伝わる（超重要）
  • エラーは.catch()までスキップして伝播

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
thenでreturn忘れ 「returnがないとundefinedが伝わる」
チェーンの途中でcatch 「catchの位置でエラー処理範囲が変わる」

20. async/await

🎯 このレッスンで読めるようになること
  • async/awaitの構文を読める
  • Promiseとの関係を理解できる
  • await忘れのバグを見抜ける
⚠️ 最重要セクション

async/awaitは2026年最もバグが多い領域です。
このセクションは特に集中して学んでください。

async/awaitとは？

async/awaitは、
「Promiseを同期処理のように書ける」構文です。 

// Promiseチェーン
fetch('/api/user')
  .then(response => response.json())
  .then(user => console.log(user));

// ⭕ async/await（同じ処理）
async function getUser() {
  const response = await fetch('/api/user');
  const user = await response.json();
  console.log(user);
}

async関数の特徴

📝 asyncのルール
  1. 関数の前にasyncをつける
  2. async関数は常にPromiseを返す
  3. async関数の中でだけawaitが使える
// async関数は常にPromiseを返す
async function hello() {
  return 'Hello';
}

// 以下と同じ
function hello() {
  return Promise.resolve('Hello');
}

// だから.then()で受け取れる
hello().then(msg => console.log(msg));  // 'Hello'

awaitの動作

awaitはPromiseが解決するまで待つキーワードです。 

async function example() {
  console.log('1. 開始');

  const result = await someAsyncTask();  // ここで一時停止

  console.log('2. 完了:', result);  // Promiseが解決してから実行
}

⚠️ 致命的バグ：await忘れ

🔴 最も多いバグ

awaitを忘れると、Promiseオブジェクト自体が変数に入ります。 

async function getUser() {
  // ❌ awaitを忘れた
  const user = fetchUser();
  console.log(user.name);  // undefined（userはPromise）

  // ⭕ 正しい
  const user = await fetchUser();
  console.log(user.name);  // "太郎"
}

⚠️ 致命的バグ：forEach + async

🔴 絶対に覚えるべきバグ

forEachの中でawaitを使っても待ってくれません。 

// ❌ forEachは待たない！
async function processItems(items) {
  items.forEach(async (item) => {
    await processItem(item);  // 待たない！
  });
  console.log('完了');  // 処理中に出力される
}

// ⭕ for...of を使う
async function processItems(items) {
  for (const item of items) {
    await processItem(item);  // ちゃんと待つ
  }
  console.log('完了');  // 全部終わってから出力
}

// ⭕ 並列で実行したいなら
async function processItems(items) {
  await Promise.all(items.map(item => processItem(item)));
  console.log('完了');
}

クイズ1：次のコードの問題点は？ 

async function getData() {
  const response = fetch('/api/data');
  const data = response.json();
  return data;
}
解説：fetch()も.json()も Promiseを返すので、両方にawaitが必要です。 awaitがないと、responseはPromiseオブジェクト、 Promise.json()はエラーになります。

クイズ2：配列の各要素を順番に処理したい。正しいのは？

解説：forEachはawaitを待ちません（コールバックを同期的に呼ぶだけ）。 for...ofならawaitが正しく動作します。 mapはPromise配列を返すだけで、awaitがありません。

クイズ3：async関数の戻り値は？ 

async function test() {
  return 42;
}
解説：async関数は常にPromiseを返します。 return 42はreturn Promise.resolve(42)と同じです。 だからtest().then(n => ...)で受け取ります。
📝 まとめ
  • async関数は常にPromiseを返す
  • awaitはPromiseが解決するまで待つ
  • await忘れ = Promiseオブジェクトがそのまま使われる（最頻出バグ）
  • forEach + async = 待たない（for...ofを使う）

レビューで指摘すべきポイント

🔴 最高危険度の問題
問題 指摘例 危険度
await忘れ 「awaitが必要。Promiseがそのまま使われている」 🔴最高
forEach + async 「forEachはawaitを待たない。for...ofを使うべき」 🔴最高

21. エラーハンドリング

🎯 このレッスンで読めるようになること
  • try/catch/finallyの使い方がわかる
  • 非同期処理でのエラー処理を理解できる
  • エラーハンドリング漏れを指摘できる

なぜエラーハンドリングが重要？

非同期処理は失敗する可能性が高いです。

⚠️ 失敗する原因
  • ネットワークエラー（サーバーに繋がらない）
  • タイムアウト（応答が遅い）
  • サーバーエラー（500エラー）
  • 認証エラー（ログイン切れ）

try/catch/finally

async function fetchData() {
  try {
    // 成功するかもしれない処理
    const response = await fetch('/api/data');
    const data = await response.json();
    return data;

  } catch (error) {
    // エラーが起きたら実行
    console.error('エラー:', error.message);
    return null;

  } finally {
    // 成功でも失敗でも必ず実行
    console.log('処理終了');
  }
}
ブロック 実行タイミング 用途
try 最初に実行 メイン処理
catch エラー時のみ エラー処理
finally 必ず最後に 後片付け

finallyの使いどころ

async function loadData() {
  const loading = document.getElementById('loading');
  loading.style.display = 'block';  // ローディング表示

  try {
    const data = await fetchData();
    displayData(data);
  } catch (error) {
    showError(error);
  } finally {
    // 成功でも失敗でもローディングを消す
    loading.style.display = 'none';
  }
}

❌ よくある間違い

// ❌ try/catch がない
async function getData() {
  const response = await fetch('/api/data');  // エラーで落ちる
  return response.json();
}

// ❌ catchで何もしない
async function getData() {
  try {
    const response = await fetch('/api/data');
    return response.json();
  } catch (error) {
    // 何もしない → 問題が隠れる
  }
}

// ⭕ 適切なエラー処理
async function getData() {
  try {
    const response = await fetch('/api/data');
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    return response.json();
  } catch (error) {
    console.error('データ取得失敗:', error);
    throw error;  // 上位に伝播させる or 代替値を返す
  }
}

エラーの再スロー

async function processData() {
  try {
    const data = await fetchData();
    return transform(data);
  } catch (error) {
    // ログを残して再スロー
    console.error('processData failed:', error);
    throw error;  // 呼び出し元でも処理できる
  }
}

errorオブジェクトの構造

catchで受け取るerrorには便利なプロパティがあります。

プロパティ 内容 例
error.message エラーメッセージ "Failed to fetch"
error.name エラーの種類 "TypeError"
error.stack 発生場所の追跡情報 デバッグ用 
try {
  await fetch('/api/data');
} catch (error) {
  console.log(error.name);     // "TypeError"
  console.log(error.message);  // "Failed to fetch"
  console.log(error.stack);    // 詳細なスタックトレース
}
📝 まとめ
  • tryで危険な処理を囲む
  • catchでエラーを適切に処理（握り潰さない）
  • finallyでクリーンアップ（ローディング解除など）
  • 必要に応じてthrowで再スロー

クイズ：finallyブロックが実行されるのは？

解説：finallyは「最終的に」という意味。 tryが成功してもcatchが実行されても、必ず最後に実行されます。 ローディング表示の解除やリソースの解放に使います。

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
try/catchがない 「エラーハンドリングが必要」
catchで握り潰し 「エラーを隠さずログ出力 or 再スローすべき」
finallyがない 「リソース解放にfinallyを使うべき」

22. 並列・直列実行

🎯 このレッスンで読めるようになること
  • Promise.all / allSettled / race を読める
  • 並列と直列の違いを理解できる
  • 不要な直列実行を指摘できる

直列 vs 並列

🍳 たとえ話：朝食を作る

直列 = トースト焼く → 卵焼く → コーヒー淹れる（順番に）
並列 = 3つ同時に進行！ 

// ❌ 直列（遅い）- 1つずつ待つ
async function slow() {
  const user = await fetchUser();      // 1秒
  const orders = await fetchOrders();  // 1秒
  const products = await fetchProducts(); // 1秒
  // 合計: 3秒
}

// ⭕ 並列（速い）- 同時に実行
async function fast() {
  const [user, orders, products] = await Promise.all([
    fetchUser(),      // 同時に開始
    fetchOrders(),    // 同時に開始
    fetchProducts()   // 同時に開始
  ]);
  // 合計: 1秒（最も遅い処理の時間）
}

Promise.all

すべてのPromiseが成功したら、結果の配列を返します。
1つでも失敗したら、即座にrejectされます。 

// 全部成功 → 結果の配列
const results = await Promise.all([
  Promise.resolve(1),
  Promise.resolve(2),
  Promise.resolve(3)
]);
console.log(results);  // [1, 2, 3]

// 1つでも失敗 → 即座にエラー
await Promise.all([
  Promise.resolve(1),
  Promise.reject('失敗'),
  Promise.resolve(3)
]);  // Error: 失敗

Promise.allSettled

すべてのPromiseが完了するまで待ちます。
成功・失敗の両方の結果を取得できます。 

const results = await Promise.allSettled([
  Promise.resolve('成功1'),
  Promise.reject('失敗'),
  Promise.resolve('成功2')
]);

console.log(results);
// [
//   { status: 'fulfilled', value: '成功1' },
//   { status: 'rejected', reason: '失敗' },
//   { status: 'fulfilled', value: '成功2' }
// ]

Promise.race

最初に完了したPromiseの結果を返します。 

// タイムアウト実装の例
const result = await Promise.race([
  fetch('/api/data'),
  new Promise((_, reject) =>
    setTimeout(() => reject('タイムアウト'), 5000)
  )
]);

使い分け早見表

メソッド 動作 使いどころ
Promise.all 全成功 or 1つ失敗で終了 全部必要な時
Promise.allSettled 全完了まで待つ 失敗も知りたい時
Promise.race 最初の1つで終了 タイムアウト実装

直列が正しい場合もある

⚠️ 注意：何でも並列化すればいいわけではない

依存関係がある場合は直列が正しい選択です。 

// ⭕ 直列が正しい例（依存関係あり）
async function checkout() {
  // 1. まずユーザー情報を取得
  const user = await getUser();

  // 2. ユーザーIDを使って注文を作成（依存！）
  const order = await createOrder(user.id);

  // 3. 注文IDを使って支払い処理（依存！）
  const payment = await processPayment(order.id);

  return payment;
}

// ❌ 間違い：依存関係があるのに並列化
// createOrderにはuser.idが必要なので、
// Promise.allにはできない！
📝 まとめ
  • 依存関係がない → Promise.allで並列化
  • 依存関係がある → 直列（await を連続）
  • 失敗しても続けたい → Promise.allSettled
  • 最速の1つでOK → Promise.race

クイズ：次のコードの問題点は？ 

async function getData() {
  const user = await fetchUser();
  const posts = await fetchPosts();
  const comments = await fetchComments();
  return { user, posts, comments };
}
解説：3つの処理に依存関係がないなら、 直列に待つ必要はありません。Promise.allで並列実行すれば、 3倍速くなる可能性があります。パフォーマンスレビューで必ず指摘すべき点です。

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
不要な直列実行 「依存関係がないならPromise.allで並列化すべき」
Promise.allで部分失敗 「allSettledで全結果を取得すべきかも」

23. Fetch API

🎯 このレッスンで読めるようになること
  • fetch()の基本的な使い方を読める
  • HTTPメソッド（GET/POST）を理解できる
  • レスポンスの処理方法がわかる

Fetch APIとは？

Fetch APIは、
サーバーとHTTP通信するためのAPIです。

📮 たとえ話：郵便局

fetch = 手紙を送って、返事を待つ
ブラウザからサーバーに「リクエスト」を送り、「レスポンス」を受け取ります。

基本的なGETリクエスト

// 最もシンプルな形
const response = await fetch('/api/users');
const users = await response.json();
console.log(users);

fetchの2段階処理

⚠️ 重要：2回awaitが必要
  1. await fetch() → Responseオブジェクトを取得
  2. await response.json() → 本文をJSONに変換
// ❌ よくある間違い
const data = await fetch('/api/users');  // これはResponseオブジェクト
console.log(data.name);  // undefined

// ⭕ 正しい
const response = await fetch('/api/users');
const data = await response.json();  // JSONに変換
console.log(data.name);  // "太郎"

POSTリクエスト

const response = await fetch('/api/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: '太郎',
    email: 'taro@example.com'
  })
});

const result = await response.json();

HTTPメソッド一覧

メソッド 用途 例
GET データ取得 ユーザー一覧を取得
POST 新規作成 ユーザーを登録
PUT 全体更新 ユーザー情報を更新
PATCH 部分更新 名前だけ変更
DELETE 削除 ユーザーを削除

レスポンスのチェック

🔴 超重要：fetchはHTTPエラーでスローしない！

fetch()は404や500でもエラーを投げません。
エラーになるのはネットワーク障害の時だけです。 

// ❌ これだけでは不十分！
try {
  const response = await fetch('/api/not-found');
  const data = await response.json();  // 404でもここに来る！
} catch (error) {
  // ネットワークエラーのみキャッチ
  // 404, 500などはキャッチされない！
}

// ⭕ 正しいエラーチェック
const response = await fetch('/api/users');

if (!response.ok) {
  // 400番台、500番台のエラー
  throw new Error(`HTTP error: ${response.status}`);
}

const data = await response.json();
💡 response.okとは

response.okは、ステータスコードが200-299の場合にtrue。
404や500の場合はfalseなので、必ずチェックしましょう。

完全なエラーハンドリング例

async function fetchUsers() {
  try {
    const response = await fetch('/api/users');

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const users = await response.json();
    return users;

  } catch (error) {
    if (error.name === 'TypeError') {
      // ネットワークエラー
      console.error('ネットワークに接続できません');
    } else {
      console.error('エラー:', error.message);
    }
    return [];
  }
}

クイズ：fetch()のレスポンスでJSONを取得するには？

解説：response.json()はPromiseを返すので、 awaitが必要です。response.dataは存在せず、 JSON.parse()はResponseオブジェクトには使えません。
📝 まとめ
  • fetch()はPromiseを返す（2回awaitが必要）
  • HTTPエラー(404,500)ではスローしない → response.okをチェック
  • ネットワークエラーはtry/catchでキャッチ
  • POSTはmethod, headers, bodyを指定

レビューで指摘すべきポイント

🔴 よくある問題
問題 指摘例
response.okのチェックなし 「fetchはHTTPエラーでスローしない。okチェック必須」
.json()のawait忘れ 「Promiseが返る。awaitが必要」
try/catchなし 「ネットワークエラーのハンドリングが必要」
