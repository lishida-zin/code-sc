## 全レベル共通の弱み

### 1. 実装演習の欠落（最大の弱点）
- クイズは4択のみ。「バグ付きコードを修正する」実装演習がない
- コードサンドボックス（CodePen/StackBlitz的なもの）がない
- **影響**: 「理解」で止まり「実装能力」に変換されにくい

### 2. レベル間の接続が弱い
- Level 3（React）→ Level 4（API）でフロント・バック統合の説明が不足
- Props型 → DTO → API Response型の連続性が不明確
- Level 5（インフラ）→ Level 6（設計）で本番運用と設計思想の関連が薄い

### 3. 「現実的な制約」の中での判断が不足
- 理想的な設計のみ提示。チーム規模・予算・時間の中での妥協点がない
- レガシーコード改善パス（Strangler Figパターン等）の言及がない
- 「いつDDDを使うべきか」「マイクロサービスに分割すべきか」の判断基準が曖昧

### 4. セキュリティの実装深度が浅い
- SQLインジェクション、XSSの「概念」は説明されるが、具体的な対策コードが不足
- CSP設定、OAuth2/OIDCフロー、CSRF対策トークンの実装例がない
- Level 8のセキュリティテストがaxe-core（a11y）のみ

## 演習HTML評価レポート

### 1. 演習の質的評価

#### **強み**

**Tier 1-3: 基礎段階 - 優秀**
- HTMLセマンティクス、JavaScriptの根本的なメカニズム（ホイスティング、型変換、Promise）など、実務で頻繁に遭遇するバグを厳選している
- 単なる「知識確認」ではなく「なぜバグが起きるのか」という因果関係を理解させる設計
- 具体的なシナリオ（「新人エンジニアが書いたコード」）で学習者の共感を引き出す工夫がある
- 説明文が詳細で、誤答選択肢の説明まで丁寧（学習効果が高い）

**Tier 4-5: 実践初級〜中級 - 実用的**
- Reactの直感的な陥穽（state のミュータブル操作、useEffect依存配列）をよく理解している
- RESTful API設計、HTTPステータスコードの誤用など「原則」を理解させるアプローチが秀逸
- SQLインジェクションなどセキュリティ脆弱性を含める判断が正しい

**Tier 6: インフラ - 実践的で現代的**
- Dockerfile のセキュリティ（rootユーザー、.envの漏洩）、マルチステージビルド、Docker Composeのヘルスチェックなど、実際のデプロイ失敗パターンを把握
- Kubernetes SecurityContext など、本番環境での実装知識が反映されている

**Tier 7-8: 設計・アーキテクチャ - 深い思考を要求**
- SOLID 原則を単なる用語ではなく、実装での具体的な問題（SRP 違反は「5つの責務の混在」など）として提示
- DDD の「境界づけられたコンテキスト」「Aggregate 整合性」という高度な概念をコード例で説明
- Value Object vs Entity の違いなど、モデリングの本質に触れている

**AI 誤りの講座 - 現代的で必要**
- AI生成コードの典型的な罠を網羅（存在しないAPI、古い書き方の混在、エッジケース、XSS）
- 「もっともらしい嘘」という表現が的確

**評価: 8/10 - 概ね良好だが、段階ジャンプがある**

```

Tier 4-5: フレームワーク・API設計レベル（統合技術）
   ↓ 自然

   ↓ ★ ここでジャンプ感がある
Tier 7: 設計・SOLID
   ↓
```

**問題点:**
- **Tier 5 → 6へのギャップ**: フロントエンド/バックエンド の基本から、いきなり Kubernetes・CI-CDに跳ぶ感覚
  - 例: Tier 5で SQL注入を学び、Tier 6で Dockerfile のセキュリティ
  - 中間ステップが不足している（DB 設計、マイグレーション、ログ管理など）
  
- **Tier 6内での跨度が広すぎる**: Dockerfile → Kubernetes → CI-CDが同一 Tier 内に混在
  - これら 3 つは独立した技術領域であり、段階的な学習が必要
